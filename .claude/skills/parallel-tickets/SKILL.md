# 병렬 티켓 — worktree 로 격리해서

## ★ 사용자가 명시적으로 병렬을 요청했을 때만 쓴다

기본값은 직렬(`ticket` 스킬)이다. 병렬은 에이전트를 여러 개 띄우고 토큰을 크게
쓰므로, **사용자가 그 규모를 요청해야 한다.** "티켓 5개 해줘"는 병렬 요청이 아니다.

## 왜 worktree 인가

사용자의 "브랜치 꼬임" 우려(꼬일거같음)는 근거가 있었다 — 실제로 한 라인 체크아웃에서
다른 라인 파일을 고치려 한 사고가 있었다. **worktree 는 물리적으로 충돌할 수 없다.**
디렉터리가 다르고 브랜치가 다르다. 그래서 병렬이 오히려 더 안전해진다.

---

## 준비 단계 — 에이전트를 띄우기 전에 직접 한다

에이전트를 먼저 띄우면 낡은 가정이 N배로 복제된다. 순서를 바꾸지 않는다.

1. **머지 여부 확인** (`branch-preflight`)

   ```bash
   git fetch --all --prune
   git log --oneline --all --grep="S15P11E102-<번호>"
   ```
   티켓마다 커밋 검색 **과** 코드 검색을 둘 다 한다. 표로 출력:

   | 티켓 | 이미 머지? | 근거 | 라인 |
   | --- | --- | --- | --- |

   **이미 머지된 티켓은 목록에서 뺀다.**

2. **티켓 본문 확인.** 한국어가 깨져 있으면 먼저 고치고 before/after 를 보여준다.

3. **라인이 섞였는지 확인.** AI 티켓과 BE 티켓을 한 배치에 넣으면 각 worktree 의
   기준 브랜치가 달라진다. 가능하면 **한 배치는 한 라인으로** 묶는다.

4. **최종 목록을 보여주고 승인을 기다린다.** 여기서 멈춘다.

---

## 실행 단계 — 승인 후

티켓당 서브에이전트 하나. 각 에이전트에게 주는 계약:

```bash
# 자기 worktree 를 만들고 그 안에서만 작업한다
git worktree add ../bomi-wt/<번호> -b "S15P11E102-<번호>-<line>-<슬러그>" origin/<line>-develop
```

각 에이전트가 반드시 지킬 것:

- **자기 worktree 밖의 파일을 건드리지 않는다**
- 테스트를 코드와 같이 쓴다
- **`ruff check` 와 `pytest` 가 둘 다 exit 0 이 될 때까지 반복한다.**
  건드린 파일의 기존 린트 실패도 자기 문제로 취급한다 — 기존 부채로 합리화하지 않는다

  ```bash
  cd robot/ai_chat
  venv/Scripts/ruff.exe check src tests
  venv/Scripts/pytest.exe -q -m "not integration and not manual"
  ```
  > worktree 마다 venv 가 없을 수 있다. 없으면 `python -m venv venv && venv/Scripts/pip
  > install -e ".[dev]"` 로 만들되, 이 비용(수십 초~분)을 병렬 이득에서 차감해 계산한다.

- **시간 의존 테스트는 주입된 시계를 쓴다.** 실제 시계 금지
- `CLAUDE.md §22a` 문서 갱신 포함
- 커밋 제목: `[영역](카테고리) S15P11E102-<번호> 제목 — 부제`
- push 후 **원격에 브랜치가 실제로 있는지 확인**한 뒤에만 링크를 보고한다

  ```bash
  git ls-remote --heads origin "<브랜치명>"
  ```
- MR 본문은 `mr-body` 의 6개 절

**게이트가 완전히 초록일 때만 성공 보고를 받는다.** 실패는 정직하게 보고하게 한다.

## 리드 역할 — 본인

- 티켓당 항목 하나로 작업 목록을 유지한다
- 최종 표를 낸다:

  | 티켓 | 테스트 | 린트 | 브랜치 원격 확인 | MR 링크 |
  | --- | --- | --- | --- | --- |

- **에이전트의 성공 주장을 그대로 옮기지 않는다.** 최소한 브랜치 존재와 테스트 수치는
  직접 확인한다 (`verify-evidence`).

## 정리

작업이 끝나고 머지된 worktree 는 제거한다. 남겨두면 `git worktree list` 가
쓰레기로 차고, 다음 세션이 그것을 현재 상태로 착각한다.

```bash
git worktree list
git worktree remove ../bomi-wt/<번호>
```

## 안티패턴

- 사용자 승인 없이 병렬로 시작한다
- 준비 단계(머지 확인)를 건너뛰고 바로 에이전트를 띄운다
- 에이전트가 worktree 밖을 고치게 둔다
- 한 배치에 여러 라인을 섞어 기준 브랜치를 헷갈리게 만든다
- 게이트가 빨간 에이전트의 보고를 성공으로 집계한다
- 끝난 worktree 를 방치한다
