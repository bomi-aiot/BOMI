# 읽기 전용 추적 — 결론만 남기고 탐색은 위임한다

**한 줄도 고치지 않는다.** 이 스킬은 판단 재료를 만드는 것이 목적이다.

## 왜 위임하는가

이 사용자의 가장 좋은 세션 몇 개가 순수 탐색이었다 — 벡터 임베딩 파이프라인
성숙도 판정, `'근처'` 지역 필터 추적, 개인화 대화 ERD 분석. 그중 하나는 조사
**중간에 사용량 한계로 끊겼다.**

파일 탐색을 서브에이전트에 넘기면 메인 스레드가 결론에 도달할 만큼 짧게 유지된다.
에이전트가 파일 덩어리를 반환하는 게 아니라 **결론만** 반환하게 하는 것이 핵심이다.

## 위임 규칙

- 서브에이전트를 쓸지 여부는 **사용자가 병렬·에이전트를 요청했거나 범위가
  여러 디렉터리·라인에 걸칠 때**만이다. 파일 한두 개면 직접 읽는 게 빠르다.
- 각 에이전트에게 **읽기 전용임을 명시**한다.
- 반환 형식을 고정한다: `file:line` 참조 + 발견 5개 + 미결 질문. 그 이상은 받지 않는다.
- 에이전트의 결과를 **그대로 믿지 않는다.** 결정적인 주장은 직접 코드를 열어
  재확인한 뒤 사용자에게 전달한다.

## 이 저장소에서 반드시 지켜야 할 것

**라인이 갈려 있다.** AI 라인 체크아웃에서는 `backend/` 에 자바가 거의 없다.
"구현이 안 됐다"가 아니라 "이 라인에 없다"다. 양쪽을 보려면 읽기 전용 worktree 를
만든다.

```bash
git worktree add --detach <스크래치경로>/be-develop origin/be-develop
# 조사가 끝나면
git worktree remove <스크래치경로>/be-develop
```

worktree 는 스크래치패드에 만든다. 작업 트리를 오염시키지 않는다.

## 상태 분류 — 이름과 주석을 믿지 않는다

컴포넌트마다 넷 중 하나로 **정직하게** 분류한다.

| 분류 | 뜻 |
| --- | --- |
| `REAL` | 구현됐고 테스트나 실제 호출 경로가 있다 |
| `WIRED` | 런타임에 호출되지만 동작을 증명하는 테스트가 없다 |
| `STUB` | 존재하지만 빈 값·no-op·하드코딩을 반환한다 |
| `ABSENT` | 설계가 요구하는데 코드가 없다 |

**docstring·주석·PROGRESS.md·클래스 이름을 근거로 쓰지 않는다.** 본문을 확인한다.
`NoVectorStoreMemorySearch` 같은 이름은 정직하지만, 정직한 이름이 곧 동작 확인은 아니다.

**아무도 호출하지 않는 컴포넌트는 `REAL` 이 아니다.** 정의를 찾은 뒤 반드시
호출부를 그렙한다. 팩토리 메서드가 정의만 있고 호출자가 테스트 하나뿐인 경우가
이 저장소에 실제로 있다.

## 출력

1. **결론 먼저** — 한 문단. 사용자가 이것만 읽고 판단할 수 있게.
2. **홉 단위 경로** — 각 홉에 `file:line` 과 상태 분류.
3. **끊긴 지점** — 어디서 사슬이 끊기는지, 첫 번째 끊김과 가장 심한 끊김을 구분해서.
4. **근거 없는 추론은 `[추론]`** 로 표시하고 근거를 같이 댄다.

## 안티패턴

- 조사 중에 "이왕 보니까" 코드를 고친다
- 에이전트가 준 결과를 검증 없이 그대로 사용자에게 전달한다
- 주석·문서를 근거로 상태를 분류한다
- 호출부 확인 없이 "구현되어 있다"고 말한다
- 파일 내용을 대량으로 응답에 붙인다 (결론이 묻힌다)
- 라인 차이를 모르고 "백엔드가 미구현"이라고 결론 낸다
