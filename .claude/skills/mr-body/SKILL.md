# MR 본문 — 고정 6개 절

**push 전에 게이트가 초록인지 먼저 확인한다.** 빨간 상태로 push 하지 않는다.
`.claude/hooks/pre-push-gate.sh` 가 자동으로 막지만, 막힌 뒤에 알게 되는 것보다
먼저 돌려보는 것이 빠르다.

```bash
cd robot/ai_chat
venv/Scripts/ruff.exe check src tests
venv/Scripts/pytest.exe -q -m "not integration and not manual"
```

## 템플릿 — 절을 빼거나 이름을 바꾸거나 순서를 바꾸지 않는다

```markdown
## 📌 작업 내용
## 🔍 주요 변경 사항
## 🧪 테스트 내용
## 📷 스크린샷
## ✅ 리뷰 요청 사항
## 📝 참고 사항
```

## 절별 규칙

**📌 작업 내용** — 무엇을 왜 했는가. **발견 경위와 판단 근거를 여기 녹인다.**
템플릿을 지킨다고 내용을 얕게 만들지 않는다. 서사를 버리지 않는 자리가 여기다.

**🔍 주요 변경 사항** — 파일·모듈 단위. 표가 산문보다 빠르다.

**🧪 테스트 내용** — **실제 수치를 적는다.**
- 좋음: `pytest 504 passed in 14.38s`, `ruff All checks passed`
- 나쁨: "로컬 테스트 완료" ← 증거가 아니다
- 미검증 항목은 여기서 숨기지 말고 「참고 사항」에 명시한다

**📷 스크린샷** — 화면 변경이 없으면 **없다고 한 줄 적는다.** 절을 비우지 않는다.
예: `백엔드·런타임 변경으로 화면 변경이 없습니다.`

**✅ 리뷰 요청 사항** — 리뷰어가 **어디를 봐야 하는지** 짚는다. "전체 확인
부탁드립니다"는 리뷰 요청이 아니다. 판단이 갈릴 수 있는 지점을 지목한다.

**📝 참고 사항** — 미검증 항목, 의도적으로 남긴 것, 갱신하지 않은 산출물.
예: `실기(젯슨) 미검증입니다. 로직만 검증했습니다.`

## 톤

**존댓말로 쓴다** ("~합니다", "~않습니다"). 표 셀 안의 짧은 값까지 포함한다.
저장소의 기존 문서(`docs/api/README.md` 등)가 이미 존댓말로 통일되어 있다.

**커밋 메시지는 이 템플릿을 따르지 않는다.** 커밋은 자유 서술이며 제목 서식만 지킨다:

```text
[영역](카테고리) S15P11E102-<번호> 제목 — 부제
```
영역은 `AI` `BE` `AI+BE` `ROBOT` `HW`, 카테고리는 `infra` `api` `jobs` `rag`
`schema` `dialogue` `prompt` `memory` `test` 같은 소문자 한 단어.

## 링크를 주기 전에 — 반드시 확인한다

2026-08 에 존재하지 않는 브랜치를 가리키는 MR 링크를 전달한 사고가 있었다.

```bash
git ls-remote --heads origin "<브랜치명>"     # 출력이 비면 링크를 주지 않는다
```

머지 대상은 라인별 develop 이다 — `ai-develop`, `be-develop`, `fe-develop`,
`robot-develop`. 단일 `develop` 이 아니다.

## 안티패턴

- 절을 빼거나 이름을 바꾼다
- 「테스트 내용」에 수치 없이 "완료"만 적는다
- 「스크린샷」을 빈 채로 둔다
- 「참고 사항」에 미검증 항목을 적지 않는다
- 서술체("~한다")로 쓴다
- 확인하지 않은 MR 링크를 준다
- 게이트가 빨간 상태로 push 한다
