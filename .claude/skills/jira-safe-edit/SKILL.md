# Jira 편집 — 한국어를 깨뜨리지 않고, 서식을 지켜서

## ★ 인코딩 — 이 스킬의 존재 이유

**유니코드 이스케이프(`\uXXXX`)로 Jira 텍스트를 절대 쓰지 않는다. 항상 raw UTF-8.**

최소 세 개 세션에서 이것 때문에 한국어가 망가졌고 매번 재수정 라운드가 붙었다.
실제로 남은 흔적: `꼬일거같음` → `易질거같음`, `쉽게 다시설명바람` → `쒬게 다시설명바람`.

**생성·수정 후에는 반드시 다시 읽어 확인한다.**

```text
1. createJiraIssue / editJiraIssue 로 raw 한국어를 그대로 전송
2. getJiraIssue 로 되읽기
3. 한국어가 그대로 렌더링되는지 눈으로 확인 — 깨졌으면 즉시 재수정
4. 확인하기 전에 "완료"라고 보고하지 않는다
```

cloudId 는 `ssafy.atlassian.net`.

## 제목 서식

```text
[영역](카테고리) 제목 — 부제
```

- 영역: `AI` / `BE` / `AI+BE` / `ROBOT` / `HW`
- 카테고리: `infra` `api` `jobs` `rag` `schema` `dialogue` `prompt` `memory` `test`
  같은 소문자 한 단어
- **티켓 번호를 제목에 넣지 않는다** — Jira 키가 이미 붙는다

## 본문 절 구조 — 이 순서

```markdown
## 무엇이 문제인가
## 왜 지금인가
## 작업 내용
## 완료 조건
(선택: ## 선행·후행 / ## 위험 / ## 미결 — 사람이 결정할 것 / ## 주의)
## 참고
```

`## 참고` 는 **항상 마지막**이며 한 줄이다:
`CLAUDE.md §N / docs/... / 선행: S15P11E102-NNN`

### `## 왜 지금인가` 가 핵심이다

이 팀이 **"이걸 안 하면 무엇이 *조용히* 망가지는가"**를 적는 자리다. 빠지면
티켓의 절반이 사라진다. 조용한 실패를 구체적으로 쓴다 — "성능이 나빠집니다"가
아니라 "어르신이 말을 걸었는데 로봇이 아무 대답도 안 합니다".

## 길이

**2,500~5,000자.** 기존 티켓(212·218·230·232·233)이 이 범위다. 크게 넘기면
읽히지 않는다. 상세 구현 계획은 티켓이 아니라 `docs/carebot/` 문서로 뺀다.

## 톤 — 존댓말

**"~합니다" / "~않습니다" / "~아닙니다".** 서술체("~한다")나 명사형 종결("대상 아님")로
쓰면 다시 고쳐달라는 요청이 온다. **표 셀 안의 짧은 값과 완료 조건 체크리스트
항목까지 전부** 포함한다.

나중에 변환하면 표 셀("있음", "대상 아님")을 빠뜨리기 쉽다. **초안 단계에서 맞춘다.**

## 담당자

관례적으로 AI/BE 티켓은 E102우동균에게 배정한다:
`712020:8fcf0488-3730-4d0f-adbe-832f1fa52a30`

## 새 티켓을 만들기 전에

1. **최근 티켓 하나를 `getJiraIssue` 로 읽어 서식을 맞춘다** (예: S15P11E102-232)
2. **이미 있는 티켓인지 확인한다.** 218 처럼 이미 상세히 작성된 티켓이 있는 경우가
   있다. 그때는 새 티켓을 만들지 말고 **코멘트를 단다.**
3. 브랜치 상태를 모르는 채로 티켓을 만들지 않는다 → `branch-preflight` 를 먼저 쓴다

## 안티패턴

- `\uXXXX` 이스케이프로 한국어를 전송한다
- 생성·수정 후 되읽기 없이 완료를 보고한다
- 서술체로 쓴다 / 표 셀만 서술체로 남긴다
- `## 왜 지금인가` 를 빼거나 일반론으로 채운다
- `## 참고` 를 중간에 둔다
- 5,000자를 크게 넘겨 구현 계획을 본문에 다 넣는다
- 이미 있는 티켓을 확인하지 않고 중복 생성한다
