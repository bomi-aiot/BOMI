# BOMI 기술 소개 - PPT 담당자용 전달본

> 이 문서는 기술을 모르는 PPT 담당자가 그대로 장표로 옮길 수 있도록 만든 최종 카피와 연출 지시서입니다.  
> 기술명을 설명하는 발표가 아니라, **BOMI가 사용자에게 왜 다르게 느껴지는지 설득하는 발표**를 목표로 합니다.

## 0. PPT 담당자가 먼저 알아야 할 한 문장

**BOMI의 기술은 더 많이 말하고 더 많이 움직이기 위한 것이 아니라, 필요한 순간에만 말하고 움직이며 관계의 선을 지키기 위해 존재합니다.**

기술 파트의 주인공은 라이브러리가 아니라 다음 다섯 가지 사용자 경험입니다.

1. **먼저 찾아감** - 여러 신호를 하나의 돌봄 시나리오로 묶습니다.
2. **말할 때를 고름** - 모든 알림을 말하지 않고 필요한 한마디만 고릅니다.
3. **위험을 먼저 봄** - 일반 답변보다 안전 판단을 먼저 수행합니다.
4. **기억의 선을 지킴** - 들은 말을 바로 믿지 않고, 동의와 위험도에 따라 나눕니다.
5. **헷갈리면 멈춤** - 사람과 장애물이 확실할 때만 움직입니다.

## 1. 레퍼런스 PPT에서 그대로 가져올 문법

HappyNurse의 기술 파트는 69~106쪽에서 다음 순서를 반복합니다.

1. 기술 파트 표지
2. 기술 키워드 3개를 먼저 제시
3. 첫 기술의 사용자 문제를 한 문장으로 제시
4. 작은 전체 구조를 보여줌
5. 다음 장부터 한 단계씩 확대
6. 핵심 알고리즘은 한 장에 하나만 설명
7. 마지막에 결과 또는 실제 사용 장면을 크게 제시
8. 다음 기술로 다시 같은 리듬을 반복

BOMI도 이 문법을 그대로 사용합니다.

- 장표 한 장에는 주장 하나만 둡니다.
- 본문은 최대 두 줄, 한 줄은 가능하면 18자 안팎으로 씁니다.
- 전체 구조를 한 번에 설명하지 말고, 작은 구조에서 한 경로만 확대합니다.
- 기술명은 제목이 아니라 화면 하단의 작은 증거 라벨로만 둡니다.
- 실제 영상에는 반드시 `실물 구동`, `Simulation`, `실센서 → Gazebo`처럼 검증 범위를 표시합니다.
- 화면 녹화는 자막 없이 틀지 않습니다. 관객이 무엇을 봐야 하는지 한 줄로 고정합니다.

## 2. 기술명을 관객 언어로 바꾸는 표

| 개발자 용어 | 장표에서 먼저 보여줄 말 | 기술명 노출 위치 |
|---|---|---|
| Scenario / State machine | 여러 돌봄이 부딪히지 않게 순서를 지키는 관제탑 | 구조도 하단 작은 글자 |
| scenarioId / commandId | 사건번호와 명령번호 | 확대 장표에서만 |
| LangGraph proactive gate | 지금 말해도 되는지 고르는 대화 문지기 | 기술 증거 라벨 |
| Safety triage | 답변보다 먼저 보는 안전 분기 | 빨간 경로 하단 |
| Local outbox | 먼저 보관하고, 연결되면 전달 | 네트워크 장표 하단 |
| FactCandidate | 아직 믿지 않은 사실 후보 | 후보 보관함 그래픽 |
| PostgreSQL | 정답과 권한을 지키는 원장 | DB 그래픽 내부 |
| Qdrant | 허용된 기억의 순서만 바꾸는 나침반 | 작은 보조 그래픽 |
| YOLO11 + ByteTrack | 사람을 찾고, 프레임 사이에서 놓치지 않는 눈 | 영상 하단 |
| 6-state tracking | 한 장면만 믿지 않는 상태 판단 | 상태 전환 장표 하단 |
| ROS2 / Nav2 | 로봇의 길찾기와 운동신경 | 시뮬레이션 하단 |
| Pico watchdog | 명령이 끊기면 스스로 멈추는 하위 반사신경 | 실물 영상 하단 |

## 3. 권장 분량과 속도

- 권장 본편: **36장, 약 6~7분**
- 평균 체류: 카피 장표 5~8초, 구조 장표 10~15초, 영상 8~12초
- 시간이 부족하면 `선택` 표시 장표를 빼서 27장까지 줄입니다.
- 영상은 발표자가 재생 버튼을 누르지 않도록 자동재생·반복·음소거 기본으로 넣습니다.
- 음성이 핵심인 영상만 MP4로 두고, 영상 자체 소리가 없어도 이해되도록 자막을 넣습니다.

# 4. 36장 기술 파트 상세 콘티

## OPENING - 기술을 먼저 이해시키는 3장

### T01. 기술 파트 표지

- 화면 문구: **보미는 어떻게 먼저 다가가고, 선을 지킬까요?**
- 화면: 집 안의 어르신과 BOMI 실물 사진을 풀블리드로 사용합니다. 사진이 없으면 로봇 실물 클로즈업을 어둡게 깔고 문구만 둡니다.
- 전환: 앞 시연 영상의 마지막 프레임과 같은 사진으로 시작해 자연스럽게 정지 화면이 되게 합니다.
- 발표: “이 경험을 가능하게 만든 기술을 다섯 가지 선택으로 설명드리겠습니다.”

### T02. 다섯 개 키워드

- 화면 문구: `먼저 찾아감 / 말할 때를 고름 / 위험을 먼저 봄 / 기억의 선을 지킴 / 헷갈리면 멈춤`
- 화면: HappyNurse 70쪽처럼 원형 키워드를 가로로 배치합니다. 처음에는 전부 회색, 발표 순서대로 한 개씩 활성화합니다.
- 전환: 5회 클릭으로 단어만 하나씩 나타나게 합니다. 설명문은 넣지 않습니다.
- 발표: 다섯 단어를 그대로 한 번 읽고 바로 넘깁니다.

### T03. 전체 구조 - 아직 설명하지 않기

- 화면 문구: **신호 → 판단 → 이동 → 대화 → 보호자**
- 화면: 전체 시스템을 아주 작고 단순하게 한 줄로 보여줍니다. `센서·일정·호출 / 백엔드 / 로봇 / AI 대화 / 보호자 웹` 다섯 덩어리만 둡니다.
- 전환: 첫 번째 `신호 → 백엔드` 경로만 컬러가 되고 나머지는 흐리게 남깁니다.
- 발표: “먼저, 여러 신호가 하나의 돌봄으로 이어지는 과정입니다.”

## CHAPTER 1 - 먼저 찾아가는 돌봄

### T04. 사용자 문제

- 화면 문구: **돌봄 신호는 한 번에 하나씩 오지 않습니다.**
- 화면: `문 열림`, `방 온도 상승`, `복약 시간`, `보미야 호출` 카드가 동시에 중앙의 로봇을 당기는 그림입니다.
- 전환: 카드 네 장이 약간 다른 방향에서 동시에 들어옵니다.
- 발표: “집 안에서는 센서와 일정, 호출이 서로 기다려주지 않습니다.”

### T05. 단순 구현의 실패

- 화면 문구: **모두 바로 실행하면, 로봇 한 대에 행동이 겹칩니다.**
- 화면: 로봇이 현관과 거실 두 방향으로 갈라지는 장면, 대화 풍선 두 개가 겹치는 장면을 크게 사용합니다.
- 전환: 네 신호의 화살표가 로봇에서 충돌하고 빨간 X가 나타납니다.
- 발표: “이벤트마다 바로 움직이면 귀가 인사 중에 복약 알림이 시작될 수 있습니다.”

### T06. BOMI의 선택 - 시나리오 문지기

- 화면 문구: **신호는 여러 번 와도, 돌봄은 한 번만 시작됩니다.**
- 화면: 네 신호가 `시나리오 문지기` 하나로 수렴하고, 통과한 한 건만 선명하게 만듭니다.
- 전환: `중복`, `이미 진행 중`, `시간 초과` 도장이 차례로 불필요한 신호 위에 찍힙니다.
- 하단 기술 라벨: `ScenarioStartGuard · State Machine`
- 발표: “먼저 시작해도 되는지 확인하고, 한 어르신에게 활성 돌봄 하나만 허용합니다.”

### T07. 사건번호를 따라가는 돌봄

- 화면 문구: **늦게 온 결과가 다른 돌봄에 붙지 않도록**
- 화면: 택배 송장 비유를 사용합니다. `사건번호 → 대화번호 → 명령번호` 세 칸을 한 줄로 배치하고, 결과가 같은 번호에만 붙는 모습을 보여줍니다.
- 전환: 잘못된 번호의 결과가 튕겨 나가고, 같은 번호의 결과만 다음 단계로 이동합니다.
- 하단 기술 라벨: `scenarioId · conversationId · commandId`
- 발표: “각 행동에 번호를 붙여, 늦게 도착한 결과가 다음 작업을 끝내버리는 일을 막습니다.”

### T08. 한 개의 시나리오 레일

- 화면 문구: **이동 → 도착 확인 → 대화 → 복귀 처리**
- 화면: 열차 노선처럼 네 단계를 가로로 배치합니다. 마지막 역은 `복귀 명령`으로 표기하고 현재 단계만 크게 확대합니다.
- 전환: 4장을 한 세트처럼 복제해 모핑합니다. 각 장에서 한 역씩 확대해도 좋습니다.
- 보조 문구: `AI 시작 지연과 전체 시간 초과도 별도로 종료`
- 발표: “대화가 끊겨도 작업을 종료하고 복귀 절차로 넘겨 다음 돌봄이 영원히 막히지 않게 합니다.”
- 주의: Robot 브랜치에서 `DEFAULT` 목적지는 현재 미지원입니다. 발표 전 실제 복귀 성공을 별도 검증하지 못하면 복귀 영상은 넣지 않고 `복귀 처리 설계`로만 설명합니다.

### T09. 증거 영상 - 선택

- 화면 문구: **백엔드 명령부터 도착 결과까지**
- 화면: 왼쪽 `MQTT NAVIGATE`, 중앙 `RViz 경로`, 오른쪽 `Gazebo 이동`, 마지막 `ARRIVED` 로그의 3분할 영상입니다.
- 영상 자막: `Simulation / MQTT → Nav2 → Navigation Result`
- 길이: 8~10초, 무음, 자동재생 1회 후 마지막 프레임 유지
- 발표: “현재 목적지 이동과 결과 회신은 시뮬레이션에서 이 흐름까지 확인했습니다.”
- 주의: `실물 자율주행 완료`라고 쓰지 않습니다.

## CHAPTER 2 - 말할 때를 고르는 AI

### T10. 기능이 많을수록 생기는 문제

- 화면 문구: **복약, 일정, 인사, 안부가 동시에 말하고 싶어 합니다.**
- 화면: 네 개의 말풍선을 화면 네 모서리에서 중앙으로 가져옵니다.
- 전환: 말풍선이 겹치며 소음처럼 보이게 합니다.
- 발표: “기능마다 직접 말하게 만들면, 좋은 기능이 많을수록 더 부담스러운 로봇이 됩니다.”

### T11. 한 문장 전환

- 화면 문구: **모두 말하면 돌봄이 아니라 잔소리입니다.**
- 화면: 배경사진과 문구만 사용합니다. 어르신이 TV를 보거나 쉬는 생활 장면이 적합합니다.
- 전환: 직전 장의 말풍선이 모두 사라지고 이 문장만 남습니다.
- 발표: 이 문장을 읽고 바로 넘깁니다.

### T12. 모든 발화를 ‘후보’로 만들기

- 화면 문구: **먼저 말하지 않고, 발화 후보를 제출합니다.**
- 화면: 복약·일정·인사·안부 카드가 `대화 문지기` 앞에 줄을 섭니다.
- 전환: 네 시스템에서 직접 스피커로 가던 선을 끊고 문지기로 다시 연결합니다.
- 하단 기술 라벨: `SpeechProposal`
- 발표: “어느 기능도 직접 스피커를 차지하지 못하고, 먼저 제안만 합니다.”

### T13. 게이트를 한 단계씩 확대

- 화면 문구: `아직 유효한가? / 지금이 조용한 시간인가? / 방금 말했는가? / 무엇이 더 중요한가?`
- 화면: 처음에는 네 질문을 작게 보여준 뒤, 클릭할 때마다 한 질문만 중앙에 140%로 확대합니다.
- 전환: 4단 모핑. 마지막에는 우선순위 표 하나만 남깁니다.
- 발표: “유효시간과 조용한 시간, 최근 발화 간격을 확인하고 마지막에 중요도를 비교합니다.”
- 주의: 실제 연동이 확인되지 않은 `TV와 사람 대화 구분`, `수면 감지`는 본문에 넣지 않습니다.

### T14. 말하기와 침묵은 둘 다 성공

- 화면 문구: **지금 필요한 한마디만. 때로는 아무 말도 하지 않도록.**
- 화면: 가장 중요한 카드 하나는 크게, 나머지는 뒤로 물러나 대기하게 합니다. 통과 카드가 없으면 스피커 아이콘이 꺼집니다.
- 전환: 클릭 1회는 `말하기`, 클릭 2회는 `침묵` 결과를 보여줍니다.
- 발표: “BOMI에서 침묵은 오류가 아니라 정상적인 선택입니다.”

### T15. 짧게 말하는 이유 - 선택

- 화면 문구: **음성은 다시 훑어볼 수 없으니까**
- 화면: 긴 답변 5문장이 두 문장으로 줄어드는 그래픽을 사용합니다.
- 보조 문구: `최대 2문장 · 조용한 시간에는 더 짧게`
- 하단 기술 라벨: `Response Shaper · Sentence TTS`
- 발표: “모든 발화가 마지막 정제기를 지나고, 듣기 쉬운 길이로 제한됩니다.”

## CHAPTER 3 - 위험을 먼저 보는 AI

### T16. 두 문장을 나란히

- 화면 문구: **“무릎이 아파”  vs  “가슴이 아파”**
- 화면: 두 문장을 같은 크기와 색으로 두고, 아직 판단 결과는 보여주지 않습니다.
- 전환: 다음 장에서 두 경로가 갈라집니다.
- 발표: “두 문장을 모두 일반 대화로 보내도, 모두 응급으로 보내도 돌봄이 아닙니다.”

### T17. 일반 대화보다 위에 있는 안전 분기

- 화면 문구: **위험 가능성은 답변 생성보다 먼저 봅니다.**
- 화면: 전체 대화 그래프를 작게 두고 가장 위의 `안전 분기`만 빨갛게 확대합니다. 일반 발화는 AI 대화로, 위험 가능성은 별도 경로로 보냅니다.
- 전환: HappyNurse의 작은 다이어그램 → 다음 장 확대 문법을 그대로 사용합니다.
- 하단 기술 라벨: `Safety Triage before LLM`
- 발표: “위험한 순간에 더 그럴듯한 답을 만들지 않고, 생성형 AI 경로를 먼저 우회합니다.”

### T18. 애매할 때는 한 문장만 확인

- 화면 문구: **진단하지 않고, 한 번 더 묻습니다.**
- 화면: 큰 말풍선 하나에 `많이 불편하세요? 가족분께 연락드릴까요?`처럼 실제 확인 구조를 보여줍니다. 개인정보가 포함된 실제 데이터는 사용하지 않습니다.
- 전환: 위험 문장이 확인 질문 한 문장으로 바뀝니다.
- 발표: “키워드 하나만으로 보호자를 부르지 않고, 필요한 경우 고정된 질문으로 재확인합니다.”

### T19. 대답이 없을 때도 흐름은 끝나지 않음

- 화면 문구: **위험을 말한 뒤의 침묵도 신호입니다.**
- 화면: 확인 질문 → 응답 대기 → 시간 초과 → 보호자 연결의 타임라인입니다.
- 전환: 시간 막대가 짧게 차고 보호자 아이콘으로 이동합니다. 실제 시간 수치는 큰 글자로 쓰지 않습니다.
- 발표: “확인 질문 뒤 답이 없으면, 안심할 근거가 아니라 추가 확인이 필요한 상황으로 봅니다.”

### T20. 전송보다 저장이 먼저

- 화면 문구: **Wi-Fi가 끊겨도 알림 자체를 잃지 않도록**
- 화면: `안전 알림 → 로컬 보관함 → 네트워크 → 백엔드` 흐름입니다. Wi-Fi가 꺼지면 보관함에 남고, 복구되면 다시 이동합니다.
- 전환: 네트워크 선만 끊고 다시 연결합니다. 알림 카드는 사라지지 않아야 합니다.
- 하단 기술 라벨: `SQLite Outbox · Retry`
- 발표: “전송에 성공한 뒤 저장하는 것이 아니라, 먼저 보관하고 나중에 전송합니다.”

### T21. 보호자 화면 증거 - 선택

- 화면 문구: **진단 결과가 아니라, 확인이 필요한 이유를 전달합니다.**
- 화면: 보호자 대시보드의 확인 항목 또는 알림 기록을 확대합니다.
- 영상 자막: `REST 조회 / 새로고침 후 반영`
- 발표: “현재 보호자 웹은 실시간 푸시가 아니라 조회 화면입니다. 그래서 시연에서는 새로고침까지 포함합니다.”
- 주의: `실시간 알림`, `119 자동 신고`, `응급상황 정확 탐지`라는 표현을 사용하지 않습니다.

## CHAPTER 4 - 기억의 선을 지키는 AI

### T22. 같은 저장 방식이면 위험한 두 문장

- 화면 문구: **“손자가 주말에 와”  vs  “아침 약 이제 안 먹어”**
- 화면: 두 문장에서 DB로 곧장 내려가는 화살표를 보여주고 큰 X로 막습니다.
- 발표: “추억과 복약 변경을 같은 방식으로 저장하면, 오인식이 돌봄 사실이 됩니다.”

### T23. 들은 말은 먼저 후보가 됨

- 화면 문구: **BOMI는 들은 말을 바로 믿지 않습니다.**
- 화면: `대화 원문 → 사실 후보 보관함`까지만 보여줍니다. DB는 아직 회색으로 둡니다.
- 전환: DB 직행 화살표를 후보 보관함으로 꺾습니다.
- 하단 기술 라벨: `FactCandidate`
- 발표: “대화에서 뽑은 정보는 우선 아직 확정되지 않은 후보로 남습니다.”

### T24. 세 개의 문지기

- 화면 문구: **동의했는가 / 피해야 할 주제인가 / 위험한 정보인가**
- 화면: 세 문을 차례로 통과하는 카드 그래픽입니다. `하루 수집 상한`은 하단 작은 안전장치로 둡니다.
- 전환: 각 문을 한 장씩 확대해 3클릭으로 설명합니다.
- 발표: “동의가 없거나 먼저 꺼내면 안 되는 인물과 관련된 정보는 반영하지 않습니다.”

### T25. 위험도에 따라 두 갈래

- 화면 문구: **대화는 기억하되, 약은 다시 묻습니다.**
- 화면: 왼쪽 `일상 기억·일정`, 오른쪽 `복약·건강·알 수 없는 유형`으로 분기합니다. 오른쪽에만 `확인 필요` 도장을 찍습니다.
- 전환: 오른쪽 경로만 확대해 다음 장으로 이어갑니다.
- 발표: “틀려도 쉽게 되돌릴 수 있는 정보와 돌봄에 직접 영향을 주는 정보를 다르게 다룹니다.”
- 주의: `모든 건강 발화를 자동으로 알아서 확인`한다고 말하지 않습니다. AI가 유형을 올바르게 분류한다는 계약 위에서 동작합니다.

### T26. 사람 확인이 들어가는 화면

- 화면 문구: **확정 · 수정 · 다시 질문 · 반영 안 함**
- 화면: 보호자 웹 `AI 확인 요청`의 실제 화면을 사용합니다. `대화 근거`, `현재값`, `제안값`, 네 액션을 차례로 확대합니다.
- 영상: 10~12초. 대시보드 → 확인 요청 → 확정 → 토스트 → 되돌리기까지 촬영합니다.
- 발표: “보호자는 대화를 감시하는 사람이 아니라, AI가 정리한 사실의 최종 결정자입니다.”

### T27. 정답 원장과 기억 나침반

- 화면 문구: **비슷하게 찾되, 정확해야 할 것은 정확하게 찾습니다.**
- 화면: `PostgreSQL 방패`와 `Qdrant 나침반`을 나란히 둡니다. 기억은 먼저 Postgres에서 어르신·공개범위·상태로 필터되고, Qdrant는 남은 카드의 순서만 바꾸게 합니다.
- 전환: `혈압약 ≈ 혈당약`이 가까워지는 장면 뒤에 Postgres 방패가 정확 조회 경로를 분리합니다.
- 하단 기술 라벨: `PostgreSQL = Source of Truth / Qdrant = Derived Ranking`
- 발표: “벡터 검색 결과의 글을 그대로 믿지 않고, 허용된 기억의 ID와 점수만 순위에 사용합니다.”

### T28. 의미 검색이 없어도 대화는 계속 - 선택

- 화면 문구: **더 똑똑해지는 기능이 멈춰도, 기본 돌봄은 계속됩니다.**
- 화면: Qdrant를 회색 OFF로 바꾸고 `키워드 × 중요도 × 최근성` 경로가 남아 움직이게 합니다.
- 발표: “의미 검색은 기본 돌봄의 필수 저장소가 아니라 보조 순위 기능입니다.”
- 주의: 임베딩과 Qdrant는 환경 설정에 따라 기본 OFF일 수 있으므로 시연 환경에서 켜진 것을 확인한 뒤에만 `의미 검색 동작 중`이라고 말합니다.

### T29. 기억과 공개는 별개

- 화면 문구: **기억한다고 해서 모두 보여주지는 않습니다.**
- 화면: `어르신 대화에만 사용`, `주 보호자 공유`, `모든 보호자 공유` 세 자물쇠 레벨을 단순하게 보여줍니다. 원본 대화와 PRIVATE 기억은 보호자 쪽으로 넘어가지 않게 선을 끊습니다.
- 영상: 대화 정보 화면에서 공유 범위 배지를 확대합니다.
- 발표: “현재 코드상 보호자 문맥에는 대화 원문과 요약이 빠지고, PRIVATE 기억도 대시보드에서 제외됩니다.”
- 주의: 운영 인증은 아직 완성 상태가 아니므로 `완전한 개인정보 보호`라는 표현은 사용하지 않습니다.

## CHAPTER 5 - 헷갈리면 멈추는 로봇

### T30. 카메라에 두 사람이 나타나는 순간

- 화면 문구: **한 명을 보다가, 두 명이 나타나면 누구를 따라가야 할까요?**
- 화면: 처음 한 명의 바운딩 박스만 보이고, 클릭하면 두 번째 사람이 들어옵니다.
- 전환: 두 번째 사람이 등장하는 순간 이동 화살표를 즉시 STOP으로 바꿉니다.
- 발표: “사람이 보인다는 사실만으로 바로 움직이면 엉뚱한 사람을 따라갈 수 있습니다.”

### T31. 찾기와 따라보기

- 화면 문구: **사람을 찾고, 프레임 사이에서 같은 대상을 이어 봅니다.**
- 화면: 한 사람의 박스와 Track ID가 여러 프레임을 건너 이어지는 짧은 애니메이션입니다.
- 하단 기술 라벨: `YOLO11n · ByteTrack`
- 발표: “탐지는 사람을 찾고, 추적은 다음 프레임에서도 같은 대상을 이어 봅니다.”
- 주의: Track ID는 사람의 신원이나 얼굴 인식 결과가 아닙니다.

### T32. 한 프레임만 믿지 않는 6가지 상태

- 화면 문구: `미탐지 / 추적 / 일시 누락 / 다중 확인 중 / 다중 인물 / 한 명 복귀 안정화`
- 화면: 상태 원을 작게 전체 표시한 뒤 `추적`만 컬러로 둡니다. 나머지 상태는 모두 `대표 대상 없음`으로 묶어 STOP에 연결합니다.
- 전환: `한 명 → 두 명 → 한 명`에 따라 현재 상태가 이동합니다.
- 하단 기술 라벨: `6-state tracking with hysteresis`
- 발표: “한 프레임의 실수로 움직이지 않도록, 여러 프레임의 관찰을 상태로 누적합니다.”

### T33. 비전 명령보다 안전 센서가 우선

- 화면 문구: **AI가 앞으로 가라고 해도, LiDAR가 멈추라면 멈춥니다.**
- 화면: 왼쪽 카메라의 `MOVE FORWARD`, 오른쪽 LiDAR의 가까운 장애물, 중앙 최종 결과 `STOP`을 크게 표시합니다.
- 전환: 전진 화살표 위에 STOP이 덮입니다.
- 보조 문구: `비전 단절 · LiDAR 단절 · 잘못된 값도 STOP`
- 발표: “AI의 희망 방향이 아니라 하위 안전 조건이 최종 이동 허가를 가집니다.”

### T34. 사람 추종 증거 GIF

- 화면 문구: **한 명 추적 → 두 명 정지 → 한 명 안정화 후 재개**
- 화면: 실제 카메라 디버그 화면과 Gazebo를 좌우 분할합니다. 1) 한 명 회전, 2) 두 명 STOP, 3) 한 명 복귀 후 약 1초 뒤 재개를 보여줍니다.
- 영상 라벨: `실제 카메라 + 실제 X4 LiDAR → Gazebo`
- 길이: 8~10초, 반복 GIF 또는 무음 MP4
- 발표: “실제 카메라와 LiDAR 입력으로 안전 판단을 만들고, 최종 이동은 Gazebo에서 검증했습니다.”
- 주의: `실물 모터 사람 추종 완료`라고 쓰지 않습니다.

### T35. 실물 로봇의 하위 반사신경

- 화면 문구: **명령이 끊기면, 가장 아래에서 멈춥니다.**
- 화면: `ROS2 명령 → Pico → 모터` 세 층을 쌓고, 명령 단절 시 Pico 단계에서 PWM이 0이 되는 모습을 보여줍니다.
- 영상: 낮은 속도로 움직이다 명령 발행을 중단해 정지하는 장면. 바퀴와 timeout/watchdog 로그를 분할 화면으로 둡니다.
- 영상 라벨: `실물 구동 / Pico watchdog`
- 발표: “전진·후진·회전 실물 구동과 명령 단절 시 정지는 확인했습니다.”

### T36. 기술 파트 결론

- 화면 문구:
  
  **필요한 순간에 먼저 다가가고**  
  **말해야 할 때만 말하며**  
  **확실하지 않으면 멈추는 돌봄**
