# BOMI 최종발표 PPT 상세 콘티

작성 기준
- 발표 시간 미기재이므로 본편 15분, Q&A 별도 기준
- 물리 슬라이드 115장, 실질 장면 약 45개
- 115장의 상당수는 새 내용을 더하는 장표가 아니라 모핑·확대·강조용 빌드 프레임
- 10~12분 발표라면 뒤의 "축약 규칙"대로 숨김 처리
- 레퍼런스 HappyNurse의 서사와 애니메이션 문법은 적극 차용하되, 브랜드 색과 메시지는 BOMI에 맞춤

## 0. 발표의 한 문장 목표

발표가 끝났을 때 평가위원이 BOMI를 "또 하나의 AI 스피커나 보호자 대시보드"가 아니라,
"환경을 감지하고, 시니어에게 직접 찾아가고, 대화를 안전하게 기억하며, 필요한 순간만 보호자에게 연결하는 통합 돌봄 로봇"으로 기억하게 한다.

발표용 한 줄 정의
> BOMI는 감지하면 찾아가고, 대화하면 기억하고, 필요한 순간 보호자와 연결하는 AIoT 돌봄 로봇입니다.

메인 태그라인
> 기다리는 AI가 아니라, 먼저 찾아가는 돌봄.

기술 파트의 세 질문
1. 센서와 일정이 동시에 들어와도 로봇이 충돌하지 않게 하려면?
2. 대화를 오래 기억하면서도 위험한 사실을 잘못 저장하지 않으려면?
3. 보호자를 안심시키면서도 시니어를 감시하지 않으려면?

## 2. 레퍼런스에서 그대로 가져올 시각 문법

1. 사진 장표와 설명 장표의 극단적 대비
   - 문제와 사용자 장면: 풀블리드 사진 + 검은 그라데이션 + 한 문장
   - 기능과 기술: 밝은 배경 + 짧은 제목 + 화면/GIF/작은 다이어그램

2. 한 장에 애니메이션을 많이 쌓기보다 슬라이드를 복제해 모프
   - 한 다이어그램을 전체로 보여준 뒤 다음 장에서 한 구간만 150~220% 확대
   - 같은 화면을 유지하고 주목할 부분만 밝게, 나머지는 65~80% 어둡게
   - 한 화면의 단계 1→2→3을 각각 별도 슬라이드로 만들어 발표자가 길을 잃지 않게 함

3. 섹션 진입은 짧은 영문 라벨과 큰 한글 제목
   - FEATURES / TECHNOLOGY / RELIABILITY처럼 작은 영문 라벨 사용
   - 제목은 설명형보다 주장형: "기억은 풍부하게, 돌봄 사실은 보수적으로"

4. 시연 화면은 기기 목업보다 실제 화면이 우선
   - 기능 첫 장만 기기 목업을 쓰고, 다음 장부터 실제 화면 녹화·실기기 영상으로 전환
   - 모든 음성 영상에는 큰 자막을 넣어 발표장 소음에도 이해되게 함

5. 기술은 용어가 아니라 문제부터
   - MQTT, Qdrant, pgvector 같은 단어를 먼저 띄우지 않음
   - "동시에 두 요청이 오면?", "혈압약과 혈당약을 헷갈리면?"을 먼저 보여준 뒤 기술을 등장시킴

## 3. BOMI 비주얼 시스템

색상
- Dark Forest: #153B37 — 다크 배경, 섹션 전환, 사진 오버레이
- BOMI Green: #176B5B — 핵심 키워드, 선, 아이콘
- Mint: #35B493 — 정상·연결·완료 상태
- Coral: #E16A4A — 긴급, 주목, 인터뷰 포인트
- Warm White: #F4F7F1 — 기본 밝은 배경
- Ink: #17211F — 본문

타이포그래피
- 한글: Pretendard 또는 SUIT, 한 종류만 사용
- 영문·숫자도 같은 패밀리 사용해 통일
- 표지 64~72pt, 섹션 제목 52~60pt, 일반 제목 38~46pt, 핵심 숫자 72~100pt, 본문 20~26pt
- 한 장의 핵심 문구는 가급적 14자 안팎, 최대 두 줄

레이아웃
- 16:9, 1920×1080 기준
- 좌우 안전 여백 80px 이상
- 기본 정렬은 좌측, 선언형 장표만 중앙 정렬
- 기술 다이어그램은 노드 7개를 넘기지 않음. 더 많으면 전체→확대 연속 장표로 분리
- 모서리 라운드는 보호자 웹 화면에만 사용하고, 발표 장표 자체는 평면적 구성을 유지

전환 속도
- Morph 0.45~0.65초
- Fade 0.2~0.35초
- 강한 장면 전환은 애니메이션 없이 Cut
- 문제 파트는 Cut, 기능·기술 파트는 Morph 중심

## 4. 115장 상세 콘티

표기
- [사진] 풀블리드 촬영/생성 이미지
- [GIF] 3~6초 반복 영상
- [MP4] 7초 이상 또는 음성 포함 영상. GIF보다 MP4 권장
- [MORPH] 직전 장표의 같은 요소를 유지한 확대·이동
- [CUT] 애니메이션 없이 즉시 전환
- [내부확인] 발표 전 실제 구현·수치·담당자 확인이 필요한 내용

연출 메모
- 2~10번은 통계를 넣지 않는다. 기획 당위성을 길게 만들지 않고 제품의 빈자리를 바로 만든다.
- 사진 속 시니어를 무기력하거나 불쌍하게 연출하지 않는다. ‘혼자 있는 평범한 생활 공간’의 톤을 유지한다.
- 12~16번은 같은 좌표의 오브젝트를 복제해 모핑한다. Selection Pane 이름 예: `!!SENSOR`, `!!ROBOT`, `!!MEMORY`, `!!GUARDIAN`.

### ACT 3. 가이드형 시연 — 30~54

시연 원칙
- 긴 홍보 영상 뒤에 라이브 시연을 붙이지 않는다.
- 이동·음성은 사전 녹화 MP4를 기본으로 하고, 대시보드 확인 동작만 라이브 선택지로 둔다.
- 영상마다 좌측 상단에 `① 감지`, `② 이동`, `③ 대화`, `④ 기억`, `⑤ 연결` 현재 단계 라벨을 고정한다.

- 1080p 기준 8~12Mbps면 충분. 4K 원본을 PPT에 그대로 넣지 않음
- 영상은 링크가 아니라 PPTX 안에 포함. 발표 폴더에는 원본 MP4도 함께 보관
- 모든 영상 첫 프레임에 상황이 보이도록 포스터 프레임 지정
- GIF는 무한 반복 때문에 핵심을 지나치게 재생할 수 있으므로 장표 체류시간을 짧게 제한
- 실기기 소리보다 발표장 자막 가독성이 우선. 자막 28~34pt, 흰색+검은 반투명 배경

## 6. 라이브 시연을 한다면 운영 방식

권장안
- 로봇 이동과 음성은 녹화본을 본편으로 사용한다.
- 보호자 웹의 확인 요청 승인 또는 복약 상태 변경 한 동작만 라이브로 한다.
- 라이브 전체 E2E는 발표 후 Q&A 또는 부스에서 별도로 보여준다.

라이브 큐
- D1: 센서 이벤트 발생
- D2: 로봇 이동 시작
- D3: 대화 시작
- D4: 대시보드 갱신
- 발표자는 “지금 눌러주세요” 같은 자연어 대신 큐 번호만 조작자에게 전달한다.

지연 중 말할 문장
1. D1→D2 지연
   “지금 BOMI는 같은 어르신에게 진행 중인 돌봄이 있는지와 반복 이벤트인지 확인하고 있습니다.”
2. 이동 중
   “경로 추종과 장애물 회피는 로봇 내부에서 처리하고, 백엔드는 도착 결과와 시나리오 순서를 관리합니다.”
3. D2→D3 지연
   “도착 결과가 같은 scenarioId로 돌아와야 대화가 시작되기 때문에 이동과 대화의 순서가 섞이지 않습니다.”
4. D3→D4 지연
   “대화 원문이 그대로 보호자에게 전송되는 것이 아니라, 공개 범위와 위험도에 따라 기록 또는 확인 요청으로 정리됩니다.”

실패 전환 규칙
- 예상 반응이 3초 이상 없으면 한 번만 재시도한다.
- 재시도 실패 시 “현장 네트워크를 고려해 동일 흐름의 녹화 화면으로 이어가겠습니다” 한 문장만 말한다.
- 같은 위치의 비상 MP4로 즉시 전환한다. 원인 설명이나 사과를 길게 하지 않는다.
- 비상 영상이 끝난 뒤 원래 콘티 55번 ‘시연 복기’로 바로 복귀한다.
- 발표 노트북의 Wi-Fi 자동 전환, 알림, 절전, 화면 잠금, 자동 업데이트를 해제한다.
- 발표 전날과 당일, 실제 노트북·클리커·HDMI·프로젝터 조합으로 콜드부팅 리허설한다.

## 7. 모핑·애니메이션 제작 규칙

1. 한 슬라이드의 Animation Pane에 7개 이상 쌓지 않는다.
   - 복제 슬라이드 + Morph가 더 안정적이고 수정도 쉽다.

2. 같은 오브젝트의 이름을 유지한다.
   - Selection Pane 이름 예: `!!ROBOT`, `!!PIPELINE`, `!!DASHBOARD`, `!!CONTEXT`, `!!STATE`.
   - 직전 장표를 복제한 뒤 위치·크기만 바꾼다.

3. 강조는 확대보다 ‘주변 감광’을 먼저 쓴다.
   - 실제 화면 위에 55~70% 검은 반투명 마스크를 두고 보고 싶은 부분만 뚫는다.
   - 강조 테두리는 BOMI Green 4~6px, 긴급은 Coral 6px.

4. 전체→확대→회수 리듬을 지킨다.
   - 예: 62 전체 아키텍처 → 63 이벤트 확대 → 68 명령 확대 → 72 상태 전체로 회수.
   - 확대만 계속하면 관객이 현재 위치를 잃는다.

5. 클릭마다 한 가지 변화만 만든다.
   - 문장 하나, 숫자 하나, 선 하나, 활성 단계 하나.
   - 새 문장과 새 다이어그램과 새 영상을 같은 클릭에 동시에 보여주지 않는다.

6. 자동 재생은 영상에만 사용한다.
   - 슬라이드 전환은 발표자가 직접 넘긴다.
   - 콜드 오픈 12~15번도 자동 전환보다 클릭 리듬을 리허설하는 편이 안전하다.

7. 전환을 섞지 않는다.
   - 문제 사진: Cut 또는 짧은 Fade
   - 기능·화면 확대: Morph
   - 섹션 표지: Cut
   - 인터뷰: Fade to black 후 영상

- 통합 시나리오 반복 성공 횟수와 성공률
- 발표용 통합 브랜치의 최신 테스트 수와 통과 결과
- 실제 구현 완료·대역·미구현 시나리오 구분

- 공식 팀원 이름과 역할

- 해당 보고 당시 실제 센서·실제 로봇은 계약과 같은 대역 스크립트를 사용했음

- 대화 문맥은 프로필·오늘 상태·최근 발화·요약·장기 기억·동의된 돌봄 기록을 선별함
- 건강·복약 사실은 자동 확정하지 않으며 일반 기억은 기본 Private
- 보호자에게 대화 원문·Private 기억을 노출하지 않는 정책이 코드에 반영됨
- Qdrant 또는 임베딩을 사용할 수 없을 때 의미 점수 없이 키워드·중요도·최신성 기반으로 축소 운영함

현재 저장소만으로 주장하면 안 되는 것
- 전체 기능이 하나의 릴리스에서 완전 통합·배포됨
- 실제 주거 환경에서 완전 자율주행·자동 복귀가 검증됨
- 산책 동행 통합 E2E 완료
- 낙상 감지·의료 진단·사용자 상태 분석 완료
- 실사용자가 확인한 정확도·의료 효과·복약 순응도 개선
- 외부 Push·문자 알림 운영 완료
- 실측하지 않은 정확도·성공률·지연·절감률

## 12. 최종 제작 체크리스트

콘텐츠
- 모든 장표 제목이 주제명이 아니라 결론 문장인가
- 기획 구간이 90초를 넘지 않는가
- 시연 전에 등장인물·상황·관전 포인트가 제시되는가
- 각 기술이 ‘왜 필요한가’에서 시작하는가
- 한 장에 새로운 주장이 두 개 이상 들어가지 않았는가
- 실제 구현 범위와 대역 범위를 혼동하지 않았는가

시각
- 한 줄 제목이 두 줄로 자동 줄바꿈되지 않았는가
- 16pt 미만 본문이 없는가. 가능하면 20pt 이상인가
- 스크린샷 글자가 발표장 뒤에서 읽히는가
- 불필요한 카드·배지·탭 UI 모양을 장표 장식으로 남발하지 않았는가
- 모든 GIF·영상의 첫 프레임이 자연스러운가
- 영상·사진의 색온도와 로봇 색상이 장표 전체에서 일관적인가
- 모핑 확대 후 다시 전체 위치를 회수하는 장표가 있는가

기술 QA
- 모든 영상이 링크가 아니라 PPTX에 포함됐는가
- 발표 폴더에 PPTX·PDF·원본 MP4·폰트·비상 영상이 함께 있는가
- 다른 PC에서 열어도 폰트 대체·영상 누락이 없는가
- PowerPoint ‘미디어 호환성 최적화’를 실행했는가
- 슬라이드 쇼 모드에서 GIF/영상 시작·종료 타이밍을 확인했는가
- 발표용 해상도와 배율에서 마우스·자막이 충분히 큰가
- 비상 영상 전환을 발표자가 키보드 없이 할 수 있는가

리허설
- 15분 버전 3회, 축약 버전 2회 이상 시간을 쟀는가
- 발표자와 조작자가 D1~D4 큐를 같은 의미로 이해하는가
- 3초 지연 멘트와 비상 영상 전환을 실제로 연습했는가
- 영상 음성이 나오는 동안 발표자가 침묵하는가
- 기술 용어를 읽는 대신 관객이 방금 본 장면을 가리키며 설명하는가
- 마지막 문장이 기능 나열이 아니라 ‘먼저 찾아가는 돌봄’으로 회수되는가

## 14. 가장 중요한 제작 우선순위

1. 최종 통합 가능한 대표 시나리오 하나를 먼저 고른다.
2. 그 시나리오의 센서→이동→대화→보호자 화면을 같은 데이터와 시간으로 녹화한다.
3. 발표용 실측 지연과 반복 성공 결과를 수집한다.
4. 위 30~54번 시연 장표를 먼저 완성한다.
5. 시연에서 실제로 보이는 장면을 근거로 59~101번 기술 장표를 만든다.
6. 마지막에 문제 사진·인터뷰·팀 장표를 붙인다.

완성도를 좌우하는 것은 115장을 채우는 일이 아니라, 시연 한 흐름의 데이터·대사·화면이 처음부터 끝까지 동일한 사건으로 보이게 만드는 일이다.
