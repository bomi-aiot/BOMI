# BOMI 하드웨어 및 이동 제어 기준

이 문서는 BOMI의 차량 구성, 연결 구조, 진행 상태와 필수 안전 기준을 정리한다.

## 1. 현재 상태

차량은 JGB37-520 엔코더 모터 4개, MDD10A 모터 드라이버와 Pico H를 사용하는
차동구동 구조다.

| 단계 | 상태 |
| --- | --- |
| 부품 배송과 조립·배선 | 완료 |
| 모터 구동 확인 | 완료 |
| 엔코더 값 확인 | 앞바퀴 완료. 뒷바퀴는 카운트 이상 |
| IMU 설정 | 완료 |
| 좌우 폐루프 속도 제어 | 완료 |
| Jetson↔Pico 프로토콜 | 통신은 실기 검증 완료. 문서(`pico-serial-protocol.md`) `## 9` 의 잠정값이 남아 있어 판본은 확정 전 |
| Odometry 보정 | 완료 (유효 트레드 0.278 m 를 2026-08-06 자이로로 실측해 반영. 명령 종료 후 관성 회전 여분은 `## 8` 참고) |
| ROS 2 실제 드라이버 | 완료, 실기로 전진·후진·좌우회전·제자리회전 검증 |
| 명령 타임아웃과 비상 정지 | 완료 |

Pico 펌웨어는 목표 회전 속도(rev/s)를 받아 엔코더 피드백으로 PWM을 맞추는
폐루프 제어까지 동작한다. 자이로 z축으로 방향을 유지하고 주행 거리를 누적한다.
펌웨어 원본은 `robot/pico/closed_loop_speed.py`다. Jetson의
`~/test/closed_loop_speed.py`에서 반입해 프로토콜 스펙과 엔코더 방향 보정
(`## 7`)을 반영했다. 올리는 방법은 [`../pico/README.md`](../pico/README.md)에
있다.

Jetson과 Pico가 주고받는 형식은 [`pico-serial-protocol.md`](pico-serial-protocol.md)가
정한다.

`robot/ros2_ws/src/core`의 `pico_driver` 노드가 `/cmd_vel`을 Pico H로 보내고
`/odom`·`/imu`를 발행한다. 시작·종료 시 정지, 명령 타임아웃(`cmd_vel_timeout_sec`
0.5초)과 Pico 통신 끊김 감시(`telemetry_timeout_sec` 1.0초)가 구현돼 있고,
가짜 시리얼로 통합 테스트를 통과한다. `mock_motor_driver`는 하드웨어 없이
시험할 때 여전히 쓴다.

기동할 때마다 정지 상태에서 자이로 영점을 다시 잰다(10초 상한). 2026-08-07
실기에서 완전히 멈춘 로봇의 자이로가 93°/분을 보고했고, yaw 는 전적으로
자이로에서 오므로(`config/ekf.yaml` 은 `/odom` 의 직진 속도와 `/imu` 의 yaw
각속도 둘만 융합한다) 회전마다 지도가 어긋난 채 겹쳤기 때문이다. 재부팅과
온도에 따라 값이 달라져 상수로 박을 수 없다. 이 설계는 바퀴 미끄러짐에는
강한 대신 자이로 바이어스에 통째로 노출된다.

뒷바퀴 엔코더는 2026-08-04 시점에 앞바퀴의 절반만 세고 있었다. 원인을 확인하지
않았고, 앞바퀴(`lf`·`rf`)만 쓰는 것으로 우회한다 — 같은 쪽 두 모터는 MDD10A 한
채널에 병렬이라 속도가 같으므로 앞바퀴만으로 충분하다. 뒷바퀴 카운트는
텔레메트리에 그대로 실려 오지만 노드가 무시한다.

현재 펌웨어의 CPR 표는 네 바퀴가 비슷한 값(LF 979 / LR 984 / RF 979 / RR 970)
이라, 절반 계수가 지금도 재현되는지는 다시 확인해야 한다.

`unknown`으로 처리한다.

## 3. 연결 구조

### 주행 제어

```text
Jetson ROS 2 /cmd_vel
→ Pico H
→ MDD10A
├─ 채널 1: 왼쪽 앞·뒤 모터
└─ 채널 2: 오른쪽 앞·뒤 모터

모터 엔코더·IMU
→ Pico H
→ Jetson ROS 2
→ Odometry
```

한 채널이 같은 쪽 모터 2개를 함께 구동하므로 좌우 두 채널로 차동구동을
제어한다. `/cmd_vel`에서 좌우 목표 속도로의 변환은 Jetson의 ROS 2 노드가
담당하고, Pico H는 그 값을 PWM과 방향 신호로 출력한다.

### 전원

```text
Jetson 전원:
4S LiPo → 5A 퓨즈 → DC-DC → Jetson

모터 전원:
3S LiPo → 15A 퓨즈 → MDD10A → 모터 4개
```

Jetson과 모터의 양극 전원은 분리한다. Jetson–Pico–MDD10A 제어 신호는 기준
전압을 공유해야 하므로 신호 GND 연결을 확인한다.

### 현관 센서

```text
문 센서 + PIR
→ Zigbee USB 동글
→ Raspberry Pi 5
→ MQTT·백엔드
```

## 4. 제어 원칙

`geometry_msgs/Twist`의 표준 의미를 유지한다.

- `linear.x`: 전후 목표 선속도
- `angular.z`: 목표 각속도

`linear.x`와 `angular.z`를 좌우 바퀴 목표 속도로 변환한다. 이 값을 PWM에 직접
복사하지 않고 최대 속도, 가감속 제한과 모터 방향 설정을 적용한다.

차동구동이므로 `linear.x == 0`이고 `angular.z != 0`인 명령은 제자리 회전으로
변환한다. 두 값이 모두 0이면 좌우 모터 출력을 0으로 만든다.

좌우 변환에는 바퀴 1회전 거리와 좌우 바퀴 간 거리가 필요하다. 두 값은 측정했다
(`## 7`). 값은 코드에 박지 않고 설정에서 주입받아 시작 시 검증한다.

`/cmd_vel` 은 단일 통로처럼 보이지만 그 앞에 조정 계층이 하나 더 있다.
여러 노드가 각자의 토픽으로 명령을 내고 `twist_mux` 가 우선순위로 하나만
통과시킨다(`core/config/twist_mux.yaml`).

| 입력 | 토픽 | 우선순위 |
| --- | --- | --- |
| 조이스틱 | `/cmd_vel_joy` | 100 |
| 보미야 호출 회전 탐색 | `/cmd_vel_search` | 90 |
| 사람 추종 | `/cmd_vel_follow` | 85 |
| 백엔드 배선 확인용 | `/cmd_vel_backend_test` | 75 |
| 키보드 | `/cmd_vel_keyboard` | 50 |

모든 입력의 `timeout` 은 0.5초라, 발행이 끊기면 그 입력은 자동으로 자리를
비운다. 조이스틱이 가장 높다는 것은 **사람이 언제든 개입해 덮어쓸 수 있다**는
뜻이며, 이것이 실물 로봇의 마지막 수동 안전장치다.

ROS 2 노드, 명령 변환, 안전 정책, Pico 통신과 하드웨어 드라이버를 분리한다.
관련 설정과 launch 파일은 `robot/ros2_ws/src/core/` 패키지가 소유한다.

## 5. 필수 안전 기준

- MDD10A는 모터 전원 역극성 보호가 없으므로 전원 연결 전 극성을 측정한다.
- 모터 2개를 한 채널에 연결하면 전류가 합산된다. 정지전류는 데이터시트 또는
  전류 제한 장비로 확인하고 MDD10A의 채널당 10A 연속 정격을 넘지 않는지
  검증한다.
- Jetson의 정확한 보드 모델과 입력 전압을 확인한 뒤 DC-DC 출력과 플러그 중심
  극성을 측정한다.
- 구매한 5A·15A 퓨즈는 임시값이다. 실제 소비전류와 배선 정격을 확인해
  확정한다.
- 퓨즈는 배터리 양극 가까이에 설치하고 전원이 연결된 상태에서 배선을 바꾸지
  않는다.
- 시작, 종료, 예외, 통신 끊김과 명령 타임아웃에서는 좌우 모터 PWM을 모두
  0으로 만든다.
- 잘못된 명령, 저전압, 엔코더 이상과 과전류 징후는 제한하거나 정지한다.
- 전진과 후진을 바꿀 때는 정지 구간과 가감속 제한을 둔다.
- 제자리 회전에도 최대 각속도와 가감속 제한을 적용한다.
- LiPo는 셀 수에 맞는 밸런스 충전을 사용하고 충전 중 방치하지 않는다.
- 저전압 경보기는 자동 차단 장치가 아니므로 소프트웨어 저전압 정지를 별도로
  구현한다.

## 6. 확인 순서

아래 항목은 완료했다.

1. 부품 모델, 수량, 손상과 커넥터 규격 확인
2. 배선, 극성, 퓨즈 위치와 공통 GND 검토
3. DC-DC 출력 전압과 극성 설정
4. Jetson, USB 허브, ReSpeaker와 스피커 연결
5. Pico 통신과 시작 시 PWM 0 확인
6. 모터 구동 확인

엔코더 펄스 수와 방향 부호, 바퀴 치수, IMU 축 방향, Pico watchdog 시간과 명령
주기도 확정했다(`## 7`).

아래 항목이 남아 있다.

1. 명령이 끝난 뒤 관성으로 더 도는 여분(육안 약 38°)을 자이로로 재고, 필요하면
   감속 제한을 넣는다. 유효 트레드 자체는 2026-08-06 자이로 실측으로 확정됐다.
2. 모터별 전류와 채널 합산 전류가 MDD10A 정격 안에 있는지 확인한다.
3. 뒷바퀴 엔코더 카운트 이상의 원인을 확인한다. 앞바퀴만 쓰는 우회 상태다.
4. 문·PIR 센서를 설치 위치에서 반복 시험해 누락과 지연을 확인한다.

과열, 냄새, 소음, 진동이나 큰 전압 강하가 발생하면 즉시 전원을 차단한다.

## 7. 확정한 값

| 항목 | 값 |
| --- | --- |
| 바퀴 지름 | 6.7 cm (바깥쪽 기준) |
| 바퀴 1회전 거리 | 0.1929 m (실효값) |
| 좌우 바퀴 중심 간 거리(기하) | 25.7 cm |
| 회전 변환에 쓰는 유효 트레드 | 27.8 cm (2026-08-06 자이로 실측). 스키드 스티어는 회전에서 바퀴가 옆으로 긁혀 기하값보다 크다. `/cmd_vel` 의 `angular.z` 변환은 이 값을 쓴다 |
| 앞뒤 바퀴 중심 간 거리 | 9 cm |
| 엔코더 CPR | LF 979 / LR 984 / RF 979 / RR 970 |
| 엔코더 방향 부호 | 전진에서 왼쪽이 음수, 오른쪽이 양수. 펌웨어에서 왼쪽을 반전한다 |
| 엔코더 핀 | C1은 GP12 / GP14 / GP10 / GP6, C2는 GP13 / GP9 / GP11 / GP7 |
| 모터 핀 | 왼쪽 방향 GP4·PWM GP5, 오른쪽 방향 GP2·PWM GP3, 20kHz |
| IMU | MPU-9250 (SparkFun SEN-13762), I2C 0x68, SDA GP26 / SCL GP27 |
| 최대 속도 | 0.8 rev/s, 약 0.154 m/s, 약 1.11 rad/s (유효 트레드 0.278 m 기준) |
| 최대 출력 | 70% (`MAX_PERCENT`). 피드포워드로 0.8 rev/s 에 약 54% 가 필요하고, 남는 16% 가 PI 보정 공간이다 |
| LiDAR | YDLIDAR X4-PRO. `base_link` 기준 장착 좌표 x=0.135 / y=0.0 / z=0.466 m (z 는 2026-08-10 마운트 변경 반영). 단일 출처는 `robot/scripts/bomi_map.sh` |

1회전 거리는 기하학적 원주(π × 6.7cm = 21.05cm)보다 8.4% 작다. 실제 주행 거리를
맞춰 얻은 실효값이라 타이어 눌림과 미끄러짐이 반영되어 있다. 기하학적 값으로
바꾸면 거리 계산이 틀어진다.

## 8. 아직 확정하지 않은 값

- 명령이 끝난 뒤 관성으로 더 도는 여분. 육안 관측 2회(각도계·자이로 아닌
  눈어림)에서 약 38°였다. 자이로 기반 실측과, 필요하면 감속 제한으로 다룬다.
  (회전에 쓰는 유효 트레드 자체는 2026-08-06 자이로 실측으로 0.278 m 확정 —
  `## 7` 참고)
- 자이로 스케일(`pico_driver.yaml` 의 `gyro_scale`). 회전각이 일정 비율로
  어긋날 때 조정하는 값이며, `robot/scripts/lib/calibrate_gyro.py` 가 권장값을
  계산해 준다
- 뒷바퀴 엔코더 카운트 이상의 원인
- Jetson 보드 모델, 입력 전압·극성과 최대 소비전력
- 모터 정격·정지전류
- Zigbee 동글의 정확한 모델
- 가감속과 방향 전환 제한
- 퓨즈, 배선과 커넥터 정격
- 저전압 정지 조건

확인되지 않은 값을 추측해 하드코딩하지 않는다.
