# S15P11E102-136 사용자 위치 기반 추종 희망 명령 구현 계획

## 목표

기존 `TrackingResult`의 현재 Track ID와 화면 위치를 재사용해 후속 주행 제어
모듈에 전달할 추종 희망 방향과 판단 이유를 생성한다. 실제 모터나 통신은
제어하지 않는다.

## 입력과 출력 계약

- 입력: `TrackingResult`, 수평 중앙 허용 범위, 전진 정지 높이 비율
- 출력: `FollowCommandResult(command, reason, track_id)`
- 명령: `stop`, `turn_left`, `turn_right`, `move_forward`
- Track ID는 실제 사용자 신원이 아니라 현재 판단에 사용한 임시 추적 ID다.

## 판단 순서와 안전 정책

1. `tracking`이 아닌 모든 상태는 `stop`으로 변환한다.
2. 대표 위치나 Track ID가 없거나 위치값이 유효하지 않으면 `stop`이다.
3. 수평 중앙 허용 범위 밖이면 거리에 앞서 좌우 회전을 요청한다.
4. 중앙일 때만 `height_ratio`를 확인한다.
5. 전진 임계값 미만이면 `move_forward`, 이상이면 `stop`이다.
6. 이전 프레임의 위치를 사용하지 않으며 후진 명령을 생성하지 않는다.

## 설정

- `horizontal_dead_zone = 0.15`: `0.0` 이상 `1.0` 미만
- `forward_threshold = 0.45`: `0.0` 이상 `1.0` 이하

두 값은 실제 카메라 시야각, 설치 높이와 사용자 크기에 맞춰 조정해야 하는
초기값이며 CLI 옵션으로 주입한다.

## 작업 범위

- 외부 라이브러리와 독립적인 추종 명령 도메인 계약
- 순수한 임계값 기반 추종 판단
- 기존 실시간 추적 파이프라인과 디버그 화면 연결
- 임계값 CLI 옵션과 검증
- 단위·통합 테스트 및 README 갱신

## 제외 범위

ROS 2, Jetson–Raspberry Pi 통신, MQTT, 모터·PWM 제어, 선속도·각속도,
LiDAR, 장애물 회피, PID, 탐색 회전, 실제 거리, 후진, 얼굴 인식과 Re-ID는
구현하지 않는다.

## 테스트 계획

- 좌우 회전, 중앙 전진과 정지, 임계값 경계
- 안전하지 않은 추적 상태와 누락된 대표 결과
- 잘못된 설정과 위치값
- 좌우 회전 우선순위와 후진 명령 부재
- 기존 추적 결과부터 추종 희망 명령까지의 통합 흐름
- 기존 탐지·추적·위치 테스트 회귀

## 완료 조건

안전한 한 명 추적에서만 이동 희망 명령을 생성하고, 불확실한 모든 입력은
정지하며 프로젝트 표준 포맷·린트·타입·docstring·테스트 검사를 통과한다.

## 미해결 및 후속 사항

- 임계값의 실제 적합성은 카메라와 로봇 장착 환경에서 검증해야 한다.
- `height_ratio`는 실제 거리가 아니므로 정밀 거리 제어에 사용할 수 없다.
- LiDAR, 비상 정지와 결합한 최종 명령은 후속 주행 제어 모듈이 결정한다.
- ROS 2 또는 다른 통신 방식의 명령 전달 계약은 후속 이슈에서 정의한다.
