# S15P11E102-122 사용자 추적 구현 계획

## 목표

Ultralytics 공식 ByteTrack 연동으로 프레임 간 사람의 임시 Track ID를 유지하고,
외부 라이브러리와 무관한 추적 결과 및 안전한 사람 수 상태를 제공한다.

## 입력과 출력 계약

- 입력: 원본 카메라 프레임, 프레임 너비·높이, 설정된 신뢰도와 누락 허용 프레임 수
- 추적기 출력: `list[TrackedPerson]`
- 최종 출력: `TrackingResult(status, person_count, track_id, position)`
- Track ID는 영상 흐름의 임시 객체 식별자이며 실제 사용자 신원이 아니다.

## 상태 정의

- `not_found`: 이전 정상 대상이 없거나 누락 허용 범위를 초과했다.
- `tracking`: 한 명의 Track ID와 기존 계산 방식의 위치를 제공한다.
- `multiple_people`: 두 명 이상이며 대표 Track ID와 위치를 제공하지 않는다.
- `temporarily_lost`: 직전 정상 대상을 허용 프레임 범위 안에서 일시적으로 놓쳤다.

## 작업 범위

- ByteTrack 어댑터와 외부 결과 변환
- 추적 도메인 계약과 프레임 기반 일시 누락 정책
- 기존 화면 위치 계산 재사용
- 실시간 화면의 Track ID와 상태 표시
- 단위·통합 테스트, README 갱신

## 제외 범위

얼굴 인식, Re-ID, 다중 인물 중 대상 선택, 실제 거리·속도·3차원 위치,
ROS2, 모터·TTS 제어, 휴식·수면 판단과 모델 최적화는 구현하지 않는다.

## 테스트 계획

- Track ID 변환과 연속 프레임 전달
- 한 명, 0명, 일시 누락, 장기 누락, 다중 인물 상태
- 잘못된 Track ID·박스·누락 설정 거부
- 추적 입력부터 기존 위치 계산과 최종 결과 전달까지의 통합 흐름

## 완료 조건

단위·통합 테스트와 프로젝트 표준 검사에 통과하고, 다중 인물에서 대표
사용자를 선택하지 않으며 문서가 실제 동작과 일치해야 한다.

## 미해결 사항

- `docs/state-machine.md`는 `MULTIPLE_PENDING`, `MULTIPLE_PERSONS`,
  `SINGLE_RECOVERY`를 포함한 후속 상태 머신을 정의한다. 이번 이슈는 Jira의
  단순 추적 상태 계약만 구현하며, 다중 인물 확인과 한 명 복귀 안정화는
  별도 실행 계획에서 기존 문서를 기준으로 구현해야 한다.
- 실제 카메라 FPS에 맞춘 누락 허용 기본값은 장비 수동 검증 후 조정할 수 있다.
- 실제 카메라와 모델에서 Track ID 유지 품질은 자동 테스트 범위 밖이다.
