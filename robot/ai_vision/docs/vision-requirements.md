# BOMI AI Vision 기능 요구사항

## 1. 문서 목적

이 문서는 BOMI 돌봄 로봇에서 사용하는 AI 비전 모듈의 기능 요구사항을 정의한다.

AI 비전 모듈은 카메라 영상을 분석해 다음 정보를 제공한다.

* 영상에 존재하는 사람의 수
* 보호대상자 추적 상태
* 보호대상자의 화면상 위치
* 보호대상자가 누워 있거나 쉬고 있을 가능성
* 로봇이 능동적으로 말을 걸어도 되는 상태인지 여부

이 문서는 AI 비전 모듈이 반드시 구현해야 하는 동작과 구현하지 않을 범위를 명확히 구분하기 위해 사용한다.

구현 결과가 이 문서와 다르다면 코드를 기준으로 문서를 변경하지 않는다. 요구사항 변경이 필요한 경우 변경 이유와 영향을 검토한 뒤 문서를 먼저 수정한다.

---

## 2. 프로젝트 배경

BOMI는 독거노인 또는 돌봄이 필요한 보호대상자를 지원하는 이동형 로봇이다.

로봇은 사용자를 따라다니며 대화하고, 일정 알림이나 개인화된 정보를 제공한다.

AI 비전 기능은 다음 두 가지 주요 목적을 가진다.

1. 로봇이 따라가야 할 보호대상자의 위치를 파악한다.
2. 보호대상자가 잠들었거나 쉬고 있을 가능성이 있을 때 로봇이 먼저 말을 걸지 않도록 한다.

AI 비전 모듈은 사람의 의료 상태를 진단하거나 로봇을 직접 제어하는 모듈이 아니다.

---

## 3. MVP 운영 전제

현재 MVP는 다음 환경을 전제로 한다.

### 3.1 보호대상자 수

* 정상 운영 환경에는 보호대상자 한 명만 존재한다.
* 영상에서 유효한 사람이 정확히 한 명 검출되면 해당 사람을 보호대상자로 간주한다.
* 보호대상자의 실제 신원을 별도로 확인하지 않는다.

### 3.2 카메라 환경

* 로봇에 장착된 단일 RGB 카메라를 기본 입력 장치로 사용한다.
* 카메라는 로봇의 전방 또는 보호대상자가 존재할 가능성이 높은 방향을 촬영한다.
* 카메라 영상은 일정한 프레임 단위로 AI 비전 모듈에 전달된다.
* 야간, 역광, 심한 가림, 화면 이탈 등의 상황에서는 판단이 불가능할 수 있다.

### 3.3 처리 장치

* 최종 실행 환경은 Jetson Orin Nano를 기준으로 한다.
* 초기 개발과 기능 검증은 일반 PC에서도 수행할 수 있어야 한다.
* 초기 구현은 Python과 Ultralytics 기반으로 진행할 수 있다.
* TensorRT 및 ROS2 최적화는 핵심 기능 검증 이후 적용한다.

## 4. 기능 범위

AI 비전 모듈의 MVP 기능은 다음과 같다.

### 4.1 사람 탐지

* 영상 프레임에서 사람 클래스를 탐지한다.
* YOLO 계열 객체 탐지 모델을 사용한다.
* 사람 이외의 객체는 보호대상자 판단에 사용하지 않는다.
* 모델 confidence가 설정된 기준보다 낮은 탐지는 유효한 사람 수에서 제외한다.
* 탐지 결과에는 최소한 다음 정보가 포함돼야 한다.

  * 바운딩 박스
  * confidence
  * 클래스 ID
  * 화면 중심 좌표

### 4.2 사람 추적

* ByteTrack을 이용해 연속된 프레임에서 동일한 사람의 Track ID를 유지한다.
* Track ID는 현재 영상 안에서 사람을 추적하기 위한 임시 식별자로만 사용한다.
* Track ID를 실제 사용자 신원으로 간주하지 않는다.
* 사람이 잠시 가려지거나 탐지가 누락돼도 설정된 허용 범위 안에서는 기존 추적 상태를 유지할 수 있다.
* 화면을 완전히 벗어나거나 장시간 탐지되지 않으면 추적 실패 상태로 전환한다.

### 4.3 보호대상자 선택

* 유효한 사람이 정확히 한 명이면 해당 사람을 현재 보호대상자로 간주한다.
* 두 명 이상이 검출되면 특정 사람을 보호대상자로 임의 선택하지 않는다.
* 가장 큰 바운딩 박스, 가장 높은 confidence 또는 기존 Track ID만으로 다중 인물 중 한 사람을 강제로 선택하지 않는다.
* 얼굴인식이나 Person Re-ID를 이용한 보호대상자 신원 확인은 MVP에서 수행하지 않는다.

### 4.4 사람 수 상태 판단

AI 비전 모듈은 유효한 사람 수와 이전 상태를 바탕으로 보호대상자 추적 상태를 결정한다.

필수 상태는 다음과 같다.

* `NOT_DETECTED`
* `TRACKING`
* `TEMPORARILY_LOST`
* `MULTIPLE_PENDING`
* `MULTIPLE_PERSONS`
* `SINGLE_RECOVERY`

상세한 상태 전환 규칙은 `docs/state-machine.md`에서 정의한다.

### 4.5 화면상 위치 계산

한 명의 보호대상자를 정상적으로 추적할 때 다음 정보를 계산한다.

* 바운딩 박스 좌표
* 바운딩 박스 중심 좌표
* 프레임 너비와 높이를 기준으로 정규화한 중심 좌표
* 보호대상자의 화면상 방향

화면상 방향은 최소한 다음 세 구역으로 구분할 수 있어야 한다.

* `LEFT`
* `CENTER`
* `RIGHT`

구역 경계는 설정값으로 관리한다.

AI 비전 모듈이 제공하는 위치는 카메라 화면 기준 방향이다. 실제 거리와 장애물은 LiDAR 또는 다른 센서가 담당한다.

### 4.6 다중 인물 처리

두 명 이상의 사람이 검출되는 상황은 정상 운영 조건에서 벗어난 예외 상황으로 처리한다.

필수 동작은 다음과 같다.

1. 한 프레임에서 두 명 이상이 검출됐다는 이유만으로 즉시 확정 상태로 전환하지 않는다.
2. 설정된 프레임 수 또는 시간 동안 다중 인물 검출이 지속되면 `MULTIPLE_PERSONS` 상태로 전환한다.
3. 다중 인물 상태에서는 보호대상자를 선택하지 않는다.
4. 다중 인물 상태에서는 능동 대화를 허용하지 않는다.
5. 주행 시스템이 사용할 수 있도록 이동 비허용 상태를 제공한다.
6. 다시 한 명만 검출되더라도 즉시 정상 추적으로 복귀하지 않는다.
7. 한 명 상태가 설정된 안정화 기간 동안 유지된 뒤 `TRACKING`으로 복귀한다.

AI 비전 모듈은 로봇의 모터를 직접 정지시키지 않는다. 상태 정보만 외부 시스템에 제공한다.

### 4.7 일시적 추적 실패 처리

사람이 순간적으로 탐지되지 않는 상황을 바로 영구적인 추적 실패로 처리하지 않는다.

다음 상황을 고려한다.

* 사람과 카메라 사이에 장애물이 잠시 지나감
* 프레임 일부에서 YOLO 탐지가 실패함
* 사람이 화면 가장자리로 이동함
* 조명 변화로 confidence가 일시적으로 낮아짐

설정된 허용시간 또는 허용 프레임 안에서는 `TEMPORARILY_LOST` 상태를 사용할 수 있다.

허용 범위를 초과하면 `NOT_DETECTED` 상태로 전환한다.

일시적 추적 실패 상태에서는 능동 대화를 허용하지 않는다.

## 5. 수면 및 상호작용 상태 추정

## 5.1 기능 목적

수면 관련 기능의 목적은 사용자가 잠들었거나 쉬고 있을 가능성이 있을 때 로봇이 능동적으로 말을 걸지 않도록 하는 것이다.

이 기능은 의료적인 수면 진단이 아니다.

다음과 같은 표현을 사용하지 않는다.

* 사용자가 실제로 수면 상태라고 확정함
* 수면 단계 또는 수면의 질을 판단함
* 의학적인 수면 장애를 진단함

기능 명칭과 결과는 수면 확정이 아니라 수면 가능성 또는 상호작용 가능 상태로 표현한다.

---

## 5.2 수면 상태

필수 상태는 다음과 같다.

* `UNKNOWN`
* `AWAKE`
* `RESTING`
* `SLEEPING_ESTIMATED`

### `UNKNOWN`

다음과 같이 판단에 필요한 정보가 부족한 상태다.

* 사람이 검출되지 않음
* 두 명 이상이 검출됨
* 신체가 심하게 가려짐
* 자세를 판단할 수 없음
* 영상 입력이 유효하지 않음
* 내부 분석 오류 발생

`UNKNOWN` 상태에서는 능동 대화를 허용하지 않는다.

### `AWAKE`

보호대상자가 서 있거나 앉아 있고, 정상적인 움직임이 관찰되는 상태다.

`AWAKE` 상태는 능동 대화 허용 후보가 될 수 있다.

단, 사람 추적 상태와 confidence 등 다른 조건도 함께 충족해야 한다.

### `RESTING`

보호대상자가 누워 있거나 장시간 편안한 자세를 유지하지만 실제 수면 여부는 확정할 수 없는 상태다.

`RESTING` 상태에서는 능동 대화를 허용하지 않는다.

### `SLEEPING_ESTIMATED`

보호대상자가 누운 상태를 일정 시간 유지하고 움직임이 매우 적어 수면 중일 가능성이 높다고 추정되는 상태다.

`SLEEPING_ESTIMATED` 상태에서는 능동 대화를 허용하지 않는다.

---

## 5.3 수면 및 휴식 상태 판단 입력

초기 MVP에서는 보호대상자의 자세와 시간에 따른 움직임 정보를 조합해
능동 대화를 제한할 필요가 있는지 판단한다.

필수적으로 검토할 정보는 다음과 같다.

* 보호대상자가 정상적으로 추적되고 있는지 여부
* 보호대상자가 서 있거나 앉아 있거나 누워 있는지에 대한 자세 정보
* 프레임 간 보호대상자의 움직임 크기
* 동일한 자세와 움직임 상태가 유지된 시간

각 정보는 단독으로 실제 수면을 확정하는 근거로 사용하지 않는다.

예를 들어 보호대상자가 누워 있다는 이유만으로 즉시
`SLEEPING_ESTIMATED` 상태로 전환하지 않는다.

자세와 움직임 정보를 계산하는 구체적인 기술은 실제 영상 테스트와
Jetson Orin Nano 성능 측정 이후 결정한다.

---
## 5.4 수면 및 휴식 상태 판단 방식 검토 후보

다음 방법은 현재 확정된 구현 요구사항이 아니며, 기술 검증을 위한 후보로 관리한다.

* 사람 바운딩 박스의 가로·세로 비율
* YOLO Pose를 이용한 신체 주요 지점 분석
* 바운딩 박스 중심점의 프레임 간 이동량
* 보호대상자 영역 내부의 프레임 차이
* Optical Flow를 이용한 움직임 분석
* 특정 공간이나 영역에 대한 ROI 활용
* 수면 또는 자세 분류 모델 활용

Codex는 활성 실행 계획에 명시되지 않은 후보 방법을 임의로 구현하지 않는다.

어떤 방법을 적용할지는 다음 기준을 비교한 뒤 결정한다.

* 실제 촬영 환경에서의 정확도
* 이불이나 가림 상황에 대한 안정성
* 카메라 각도에 대한 민감도
* Jetson Orin Nano에서의 처리속도
* 구현 및 테스트 기간
* 추가 데이터셋 필요 여부
---

## 5.5 누운 자세 판단

초기 구현에서는 다음 방법을 단계적으로 검토한다.

1. 바운딩 박스 가로·세로 비율
2. 보호대상자 바운딩 박스의 방향과 위치
3. YOLO Pose를 이용한 신체 주요 지점 분석
4. 침대 ROI와 자세 정보 결합

바운딩 박스 비율만으로 수면을 확정하지 않는다.

다음 상황에서는 비율 기반 판단이 잘못될 수 있다.

* 사람이 웅크리고 앉음
* 카메라 각도가 기울어짐
* 신체 일부가 이불에 가려짐
* 바운딩 박스가 신체 전체를 포함하지 못함
* 사람이 카메라를 향해 누움

따라서 누운 자세 결과에는 confidence 또는 판단 가능 여부를 함께 제공하는 것이 좋다.

---

## 5.6 움직임 판단

보호대상자의 움직임은 프레임 간 정보를 이용해 계산한다.

검토 가능한 입력은 다음과 같다.

* 바운딩 박스 중심점 이동 거리
* 바운딩 박스 크기 변화
* Pose keypoint 이동 거리
* 보호대상자 ROI 내부의 프레임 차이
* Optical Flow

초기 MVP에서는 계산 비용과 구현 난도를 고려해 단순한 방식부터 적용한다.

움직임 기준값은 카메라 해상도와 프레임 속도에 영향을 받으므로 설정값으로 관리한다.

---

## 5.7 능동 대화 허용 조건

능동 대화는 다음 조건을 모두 만족할 때만 허용한다.

1. 유효한 사람이 정확히 한 명이다.
2. 보호대상자 추적 상태가 `TRACKING`이다.
3. 수면 관련 상태가 `AWAKE`다.
4. 결과 confidence가 설정된 최소 기준 이상이다.
5. 영상이 설정된 최대 지연시간보다 오래되지 않았다.
6. 내부 처리 오류가 없다.

다음 상태에서는 능동 대화를 허용하지 않는다.

* `NOT_DETECTED`
* `TEMPORARILY_LOST`
* `MULTIPLE_PENDING`
* `MULTIPLE_PERSONS`
* `SINGLE_RECOVERY`
* `UNKNOWN`
* `RESTING`
* `SLEEPING_ESTIMATED`

능동 대화를 금지하는 것은 로봇의 모든 응답을 차단한다는 의미가 아니다.

사용자가 먼저 음성으로 로봇을 호출한 경우의 응답 정책은 대화 시스템에서 별도로 결정한다.

## 6. 입력 요구사항

AI 비전 모듈은 최소한 다음 입력 방식을 지원할 수 있도록 설계한다.

### 6.1 개발 단계

* 로컬 영상 파일
* USB 웹캠
* 노트북 내장 카메라

### 6.2 통합 단계

* ROS2 `sensor_msgs/Image`
* ROS2 `sensor_msgs/CompressedImage`는 필요 시 추가 검토

핵심 분석 로직은 입력 방식에 직접 의존하지 않아야 한다.

영상 파일, 웹캠, ROS2 입력은 각각 adapter 계층에서 처리한다.

## 7. 출력 요구사항

AI 비전 파이프라인의 최종 결과에는 최소한 다음 정보가 포함돼야 한다.

### 7.1 프레임 정보

* 처리 시각
* 원본 프레임 식별 정보 또는 시퀀스 번호
* 프레임 너비
* 프레임 높이
* 추론 처리시간

### 7.2 사람 정보

* 유효한 사람 수
* 보호대상자 Track ID
* 보호대상자 confidence
* 보호대상자 바운딩 박스
* 보호대상자 중심 좌표
* 정규화된 중심 좌표
* 화면상 방향

보호대상자를 선택할 수 없는 경우 Track ID와 위치 정보는 `None` 또는 명시적인 미지정 값으로 반환한다.

### 7.3 상태 정보

* 사람 추적 상태
* 수면 추정 상태
* 능동 대화 허용 여부
* 이동 허용 여부 또는 안전 상태
* 상태 판단 이유
* 전체 결과 confidence
* 오류 코드 또는 오류 메시지

### 7.4 결과 예시

정상 추적 상태:

```json
{
  "person_count": 1,
  "person_state": "TRACKING",
  "track_id": 7,
  "confidence": 0.91,
  "center_x_normalized": 0.54,
  "center_y_normalized": 0.62,
  "direction": "CENTER",
  "sleep_state": "AWAKE",
  "interaction_allowed": true,
  "movement_allowed": true,
  "reason": "한 명의 보호대상자를 정상적으로 추적 중입니다."
}
```

다중 인물 상태:

```json
{
  "person_count": 2,
  "person_state": "MULTIPLE_PERSONS",
  "track_id": null,
  "confidence": 0.0,
  "direction": null,
  "sleep_state": "UNKNOWN",
  "interaction_allowed": false,
  "movement_allowed": false,
  "reason": "두 명 이상의 사람이 지속적으로 검출되어 보호대상자를 특정할 수 없습니다."
}
```

수면 추정 상태:

```json
{
  "person_count": 1,
  "person_state": "TRACKING",
  "track_id": 4,
  "confidence": 0.83,
  "direction": "RIGHT",
  "sleep_state": "SLEEPING_ESTIMATED",
  "interaction_allowed": false,
  "movement_allowed": true,
  "reason": "침대 영역에서 누운 자세와 낮은 움직임이 지속되고 있습니다."
}
```

## 9. 오류 및 예외 처리 요구사항

### 9.1 모델 로딩 실패

모델 파일이 없거나 로딩에 실패하면 명확한 오류를 발생시킨다.

실패한 상태에서 임의의 정상 결과를 생성하지 않는다.

### 9.2 영상 입력 실패

카메라 또는 영상 파일을 열 수 없으면 원인과 입력값을 포함한 오류를 반환한다.

실행 중 프레임 읽기에 실패하면 다음 중 적절한 처리를 수행한다.

* 영상 파일이 끝난 경우 정상 종료
* 카메라 프레임이 일시적으로 누락된 경우 재시도
* 연속 실패가 기준을 초과한 경우 안전 상태로 전환

### 9.3 추론 실패

특정 프레임의 추론에 실패하면 오류를 기록하고 해당 프레임 결과를 안전 상태로 반환한다.

권장 안전 결과:

* `person_state`: `NOT_DETECTED` 또는 별도 `ERROR`
* `sleep_state`: `UNKNOWN`
* `interaction_allowed`: `false`
* `movement_allowed`: `false`

### 9.4 잘못된 설정

다음과 같은 설정은 프로그램 시작 시 검증한다.

* confidence가 0.0 미만 또는 1.0 초과
* 확인 프레임 수가 1 미만
* 시간값이 음수
* ROI 좌표가 허용 범위를 벗어남
* 이미지 크기가 0 이하
* 존재하지 않는 모델 경로

## 10. 비기능 요구사항

### 10.1 가독성

* 모든 코드는 `docs/code-style.md`를 따른다.
* Python 파일, 클래스, 함수에는 한국어 docstring을 작성한다.
* 중요한 정책값과 상태 전환에는 한국어 설명을 작성한다.

### 10.2 테스트 가능성

* 상태 머신과 좌표 계산은 모델 없이 단위 테스트할 수 있어야 한다.
* YOLO와 ByteTrack은 adapter 또는 인터페이스 뒤에 분리한다.
* 카메라 입력 없이 저장 영상 또는 가짜 입력으로 파이프라인을 검증할 수 있어야 한다.

### 10.3 확장성

* YOLO 모델을 교체할 때 핵심 상태 로직을 수정하지 않아야 한다.
* 입력 방식을 웹캠에서 ROS2로 변경해도 핵심 분석 로직을 재사용할 수 있어야 한다.
* 수면 자세 분석 방식을 바운딩 박스에서 Pose 기반으로 교체할 수 있어야 한다.

### 10.4 성능

초기 기능 검증 단계에서는 정확성과 안정성을 우선한다.

이후 Jetson Orin Nano에서 다음 항목을 측정한다.

* 평균 FPS
* 프레임별 추론시간
* GPU 사용량
* GPU 메모리 사용량
* CPU 사용량
* 전체 파이프라인 지연시간

성능 기준은 실제 카메라와 통합 환경 테스트 후 확정한다.

### 10.5 개인정보 보호

* 영상 원본을 기본적으로 외부 서버에 전송하지 않는다.
* 디버그 영상 저장은 설정을 통해 활성화한 경우에만 수행한다.
* 저장 영상에는 보호대상자의 개인정보가 포함될 수 있음을 고려한다.
* 불필요한 얼굴 이미지와 장시간 영상을 저장하지 않는다.
* 얼굴인식용 생체정보를 수집하지 않는다.

## 13. 기능별 수용 기준

### 13.1 사람 탐지 완료 기준

* 사람이 없는 영상에서 빈 목록을 반환한다.
* 한 명의 사람이 있는 영상에서 사람 바운딩 박스를 반환한다.
* 사람 이외 객체를 보호대상자로 반환하지 않는다.
* confidence 임계값을 설정으로 변경할 수 있다.
* 잘못된 프레임 입력을 안전하게 처리한다.

### 13.2 사람 추적 완료 기준

* 동일한 사람이 연속 프레임에서 이동할 때 Track ID가 대체로 유지된다.
* Track ID가 없는 결과를 안전하게 처리한다.
* 사람을 놓친 한두 프레임으로 프로그램이 종료되지 않는다.
* 두 명의 사람에게 서로 다른 Track ID가 부여된다.

### 13.3 상태 머신 완료 기준

* 0명이 지속되면 `NOT_DETECTED`를 반환한다.
* 1명이 정상 검출되면 `TRACKING`을 반환한다.
* 두 명 이상이 순간 검출되면 `MULTIPLE_PENDING`을 반환한다.
* 두 명 이상이 기준 이상 지속되면 `MULTIPLE_PERSONS`를 반환한다.
* 다중 인물 상태에서 한 명으로 줄어들면 `SINGLE_RECOVERY`를 반환한다.
* 한 명이 안정적으로 유지되면 `TRACKING`으로 복귀한다.
* 음수 사람 수와 같은 잘못된 입력을 거부한다.

### 13.4 수면 상태 완료 기준

* 사람이 없으면 `UNKNOWN`을 반환한다.
* 다중 인물이면 `UNKNOWN`을 반환한다.
* 서거나 앉은 자세가 안정적으로 관찰되면 `AWAKE` 후보를 반환한다.
* 누운 자세가 일정 시간 지속되면 `RESTING`을 반환한다.
* 누운 자세와 저움직임이 기준시간 이상 지속되면 `SLEEPING_ESTIMATED`를 반환한다.
* 큰 움직임 또는 기립 자세가 지속되면 `AWAKE`로 복귀한다.
* `UNKNOWN`, `RESTING`, `SLEEPING_ESTIMATED`에서 능동 대화를 허용하지 않는다.

### 13.5 최종 파이프라인 완료 기준

* 영상 프레임 하나를 입력하면 구조화된 비전 결과를 반환한다.
* 외부 모델 객체가 최종 결과에 직접 포함되지 않는다.
* 오류 발생 시 안전한 결과를 반환한다.
* 설정값 변경을 위해 핵심 코드를 수정할 필요가 없다.
* 사람 탐지, 추적, 상태 판단을 개별적으로 테스트할 수 있다.
* ROS2 없이도 영상 파일과 웹캠으로 기능을 검증할 수 있다.

## 14. 확정 상태

### 14.1 확정된 항목

* YOLO 계열 모델을 이용해 사람을 탐지한다.
* ByteTrack을 이용해 프레임 간 사람을 추적한다.
* 정상 환경에는 보호대상자 한 명이 존재한다고 가정한다.
* 유효한 사람이 정확히 한 명이면 해당 사람을 보호대상자로 간주한다.
* 두 명 이상이 검출되면 특정 사람을 임의로 보호대상자로 선택하지 않는다.
* 다중 인물 상태에서는 능동 대화를 허용하지 않는다.
* 잠들었거나 쉬고 있을 가능성이 있으면 능동 대화를 허용하지 않는다.
* AI 비전 모듈은 모터와 TTS를 직접 제어하지 않는다.
* 얼굴인식과 Person Re-ID는 MVP에서 제외한다.

### 14.2 구현 방법이 미확정인 항목

* 최종 YOLO 모델 종류
* 기본 confidence 임계값
* 다중 인물 확인 기준
* 한 명 복귀 안정화 기준
* 일시적 추적 실패 허용시간
* 누운 자세 판별 방식
* 움직임 계산 방식
* 수면 및 휴식 상태 전환시간
* 최종 ROS2 인터페이스

### 14.3 기능 적용 여부를 검토 중인 항목

* 침대 또는 특정 공간 인식
* 침대 ROI 설정
* YOLO Pose 사용
* 수면 영상 데이터셋을 이용한 추가 학습
* Optical Flow 사용
* 별도의 자세 분류 모델 사용

검토 중인 항목은 활성 실행 계획에서 구현 대상으로 명시되기 전까지
필수 기능으로 취급하지 않는다.
