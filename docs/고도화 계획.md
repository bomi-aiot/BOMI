# 고도화 계획

> 2026-08 시연까지 구현·검증한 범위를 기준으로, 이후 확장 시 착수할 항목을 정리한
> 문서입니다. 각 항목은 현재 상태의 근거(코드 위치 또는 기록 문서)와 고도화 방향을
> 함께 적습니다. 상태 표기는 [진행 상황](<carebot/진행 상황.md>)의 구분을 따릅니다 —
> "구현됨"과 "실기 검증됨"은 다른 상태입니다.

## 1. 대화 AI

| 항목 | 현재 상태 | 고도화 방향 |
| --- | --- | --- |
| 의미 검색 상시 운영 | 구현 완료. 코드 기본값은 비활성(`EMBEDDING_ENABLED`·`QDRANT_HOST` 빈 값)이며 시연 서버에서 2026-08-10 활성화한 기록이 있음 | 임베딩 과금 정책을 정한 뒤 기본 활성으로 전환. 재색인 절차는 `embedding_status` 부기 컬럼 기반 |
| 기억 정정 | 로봇은 `operation: "CREATE"` 고정(`fact_contract.py`). 취소(CANCELLED_BY_SENIOR)는 구현됨 | 백엔드 `fact_candidate`에 UPDATE/supersedes 경로를 추가하고 로봇이 모순 발화 감지 시 후보에 supersedes 힌트를 첨부 |
| 일정 목적지·이동 시간 안내 | 미착수 (구현 계획 P1-A7·A8) | `careRecords` 목적지 구조 합의 후 EVENT 문맥 후보로 등록. 이동 시간은 경로 API 도입 결정이 선행 |
| 감정 대화의 침묵 허용 | 미착수 (Phase 6). `EMOTIONAL_IDLE_TIMEOUT_SEC` 다이얼 자체가 없음 | 직전 인텐트가 emotional이면 리슨 타임아웃을 연장 |
| 능동 발화 dispatcher | `speech_proposal` 큐에 적재만 되고 발화로 나가지 않음 (P1-a) | 원자적 claim 후 proactive 그래프 호출로 배선 |
| 체크포인트 보존 정책 | LangGraph 체크포인트에 민감 문맥이 무기한 누적 (P1-c) | ctx 비영속화 또는 보존 기간 정책 도입 |
| 오디오 임계 실측 | `ECHO_GUARD_SEC` 등은 추정값. 측정 항목은 [오디오 에코 바지인 검증](<hardware/오디오 에코 바지인 검증.md>)에 정리됨 | 실제 스피커·마이크 배치에서 측정 후 확정 |

## 2. 주행·비전

| 항목 | 현재 상태 | 고도화 방향 |
| --- | --- | --- |
| 접근 주행 상시화 | `approach_enabled`·`search_enabled`·`zigzag_enabled` 전부 기본 비활성. launch 파일이 `search_enabled`를 노출하지 않는 결함 기록 있음 ([실기 통합 가이드](<scenario/실기 통합 가이드.md>)) | 실기 안정성 확인 후 기본 활성 전환, launch 파라미터 노출 정리 |
| 사용자 상태 인식 | 사람 추적(상태머신 §1~§13)은 구현·인용됨. 사용자 상태·허용 판정(§14~§21)은 미구현 | 설계 문서 기준으로 단계적 구현 (robot/ai_vision/docs/state-machine.md) |
| 비전 요구사항 잔여 단계 | 9단계 중 1~4단계 완료 | 5단계 이후는 robot/ai_vision/docs/vision-requirements.md 의 진척 표기를 따라 착수 |
| 산책 시나리오(로봇 측) | 백엔드 `WalkOrchestrator`는 구현 완료. 로봇 측은 FOLLOW 스텁 회신까지 | 실기 추종 품질 확보 후 로봇 측 산책 흐름 연결 |

## 3. 백엔드·데이터

| 항목 | 현재 상태 | 고도화 방향 |
| --- | --- | --- |
| 현관 방향 판정 상시화 | `direction-resolution-enabled` 기본 비활성 — DOOR_OPENED 단독으로 시나리오 시작 | PIR 상관 창(15초) 실측 후 기본 활성 전환 |

| 시나리오 타임아웃 복원 | 시연용으로 20분→10분 단축(`SCENARIO_ACTIVE_TIMEOUT:10m`) | 운영 전환 시 값 재검토 |
